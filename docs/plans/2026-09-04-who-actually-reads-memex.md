# 아무도 읽지 않는다 — memex 정체성과 저니 재설계

> 이 문서는 가정이 아니라 볼트의 로그에서 시작한다. 두 스킬(ux-strategy, journey-mapping)이
> 공통으로 거는 첫 조건이 "증거 없는 다이어그램은 그 자체가 가정"이라는 것이고,
> memex는 자기 사용 기록을 스스로 들고 있는 드문 제품이다.

## 0. 한 줄

**설계 문서는 "앱이 유일한 문"이라고 적었고, 로그는 앱이 전체 읽기의 0.36%라고 말한다.**
사람은 읽지 않는다. 그리고 읽지 않는 것이 실패가 아니라 이 제품이 실제로 파는 것이다.

## 1. 실측

### 어디서 읽히나 (`retrieval_log`, n=4,206)

| 표면 | 건수 | 비중 |
|---|---:|---:|
| `recall` — 프롬프트 시점 자동 조회 | 3,960 | 94.4% |
| `mcp` — 에이전트가 `search_notes` 호출 | 206 | 4.9% |
| `cli` | 25 | 0.6% |
| **`ui` — 앱** | **15** | **0.36%** |

조회가 곧 주입은 아니다. `injected` 컬럼이 생긴 뒤 기록만 보면 주입 50건 · 미주입 109건으로,
게이트가 3분의 2를 걸러낸다. 그래도 사람이 앱에서 읽은 15건과는 자릿수가 다르다.

**계측 시점 편향을 확인했다.** 앱 계측은 2026-08-29에 붙었다. 그날 이후로만 잘라도
recall 867 · mcp 88 · ui 15 · cli 7이다. 게다가 앱 기록은 **2026-08-29 하루가 전부이고
그 뒤로 0이다.** 편향을 걷어내면 결론이 약해지는 게 아니라 더 선명해진다.

### 사람이 남긴 흔적

| | |
|---|---:|
| 사람이 손으로 쓴 노트 (`source='manual'`) | **4** / 1,374 |
| 앱 채팅 턴 (`chat_turns`) | **4** |
| 승인 대기 중인 `rule` | 0 |

정정 86건은 전부 에이전트가 대화 중에 쓴 것이다. 앱에서 사람이 만든 정정은 사실상 없다.

## 2. 정체성 — 무엇을 팔고 있나

`2026-08-28-what-memex-is.md`가 확정한 넷 중 하나가 **"데스크탑 앱은 잘못 기억한 것을
바로잡는 유일한 문"**이었다. 그 문은 열리지 않았다. 4번 열렸다.

로그가 말하는 실제 제품은 이것이다.

> **memex는 대화에 조용히 붙는 기억이다.** 사람이 자기 과거를 다시 설명하지 않게 만드는 것이
> 값이고, 그 값은 사람이 아무것도 하지 않을 때 가장 크다.

| 볼트를 훑어본다 | 낮음 (15회가 증명) | 중간 | **과잉투자** |

세 번째 줄이 아프다. **가장 많이 투자한 표면이 가장 안 원하는 것이다.**

## 3. 왜 정정이 안 일어나나

정정 루프가 끊긴 곳은 "고치기"가 아니라 **"틀린 걸 알아채기"**다.

```
에이전트가 기억을 주입한다  →  AI가 그걸 근거로 답한다  →  ?  →  사람이 고친다
                                                        ↑
                                              여기에 접점이 없다
```

오늘 세션이 그 증거다. 상태 노트 115건이 낡은 주장을 들고 있었고, **에이전트가 전부 읽기
전까지 아무도 몰랐다.** 트라이얼 60일은 14일로 바뀐 지 한 달이 지났는데 Product Hunt 카피는
아직 60일이라고 말한다. 사람이 안 읽으니 못 잡는다.

### 전환의 네 힘 (왜 앱을 안 여는가)

| 힘 | 크기 | 내용 |
|---|---|---|
| Push (지금 방식에서 밀어냄) | **없음** | 대화가 이미 답을 준다 |
| Pull (앱으로 당김) | **약함** | 열어봐야 새로 볼 게 없다 |
| Anxiety | 없음 | |
| Habit (지금 방식 유지) | **강함** | 하루가 대화 안에서 흐른다 |

Push + Pull < Anxiety + Habit. 그래서 안 연다. **앱을 더 예쁘게 만들어도 이 부등호는 안 바뀐다.**

## 4. 현재 저니 (실측 기반)

한 명, 한 시나리오: 볼트 주인이 평소 하루를 보낸다.

| 국면 | ① 대화를 연다 | ② memex가 주입한다 | ③ AI가 답한다 | ④ 틀렸다 | ⑤ 대화가 끝난다 |
|---|---|---|---|---|---|
| **행동** | 질문을 친다 | (없음 — 자동) | 답을 읽는다 | (없음) | (없음 — 자동 저장) |
| **접점** | Claude Code / Desktop | `recall` 훅 | 대화 | **없음** | `save_note` |
| **생각** | | | "얘가 아는구나" | "…어? 이거 아닌데" | |
| **감정** | 무심 | 무심 | 안심 | **찜찜함** | 무심 |
| **아픔** | | | | **말할 자리가 없다** | 틀린 채로 저장된다 |
| **빈도** | 하루 여러 번 | 하루 133~1,614회 | 매번 | 드물게 알아챔 | 대화마다 |

**진실의 순간은 ④다.** 그리고 거기에 접점이 하나도 없다. 지금 설계는 그 사람이 나중에
앱을 열어 스스로 발견하기를 기다린다. 로그가 말한다 — 안 온다.

## 5. 미래 저니 — 정정을 대화 안으로

바꾸는 것은 ④ 하나다. 나머지는 이미 작동한다.

| 국면 | ③ AI가 답한다 | **④ 틀렸다** | ⑤ 대화가 끝난다 |
|---|---|---|---|
| **행동** | 답을 읽는다 | **"그거 아니야"라고 말한다** | |
| **접점** | 대화 | **대화 (같은 자리)** | `save_note` |
| **생각** | "얘가 아는구나" | "고쳐두면 다음엔 맞겠지" | |
| **감정** | 안심 | **처리됨** | |
| **기회** | 주입한 기억의 출처를 한 줄로 밝힌다 | **틀렸다는 말을 정정으로 받는 MCP 도구** | 정정이 다음 주입에 반영됐음을 알린다 |

### 이것이 요구하는 것

1. **주입된 기억이 사람에게도 보여야 한다.** `recall`은 이미 제목과 id를 붙인다
   (`apps/cli/src/services/recall/client.ts:29`). 다만 그 블록은 **모델에게 가는 것이고
   사람은 안 본다.** 지금 값이 0인 것은 노출이 없어서가 아니라 노출의 수신자가 사람이 아니어서다.
   AI가 답에 "이건 #1767에서 가져왔어요"를 한 줄 얹는 것이 가장 싼 형태다
2. **"그거 아니야"를 받는 쓰기 경로.** 대화 안에서 정정이 완결돼야 한다. 앱으로 보내면
   4번의 전례가 반복된다
3. **앱은 감사(監査) 도구로 내려간다.** 없애지 않는다. 다만 유일한 문이 아니라
   가끔 열어보는 창고 점검용이다

## 6. Opportunity Solution Tree

```
결과: 사람이 판정한 기억이 주당 늘어난다
   │
   ├── 기회 A: "틀린 걸 내가 안 봐도 알려줬으면"   ← 착수
   │      ├── 해법 A1: 주입한 기억의 출처를 대화에 한 줄로 노출
   │      ├── 해법 A2: "그거 틀렸어"를 받는 MCP 쓰기 도구
   │      └── 해법 A3: 정정 후 "다음부터 반영됨" 확인 한 줄
   │
   ├── 기회 B: "쌓인 신호를 볼 시간이 없다" (160건 미처리)
   │      └── 해법 B1: 신호를 대화 끝에 한 건씩 흘린다 (앱 백로그 금지)
   │
   └── 기회 C: "볼트를 훑고 싶다"  ← 착수하지 않음. 15회가 증명함
```

**A를 먼저 하는 이유:** 리프 기회 중 유일하게 진실의 순간에 붙어 있고, 다른 둘은
사람을 앱으로 데려와야 성립한다.

### 가장 위험한 가정

> 우리는 **주입된 기억의 출처를 사람이 읽는 답 안에 노출하면** **볼트 주인이** **틀린 기억을
> 그 자리에서 부정하게 될 것**이라고 믿는다. **주당 사람이 판정한 기억이 0에서 유의미하게 오르면**
> 맞았다고 본다.

반증 가능하다. 출처를 노출해도 아무도 부정하지 않으면, 사람은 애초에 정확성에 관심이 없고
memex는 정정 없는 편의 도구다. 그러면 앱의 교정 화면 전체가 근거를 잃는다.

**가장 싼 검증:** 코드 없이 한 주. `recall` 블록은 이미 제목을 들고 오므로, 규칙 한 줄로
"주입된 기억을 근거로 답했으면 어느 노트였는지 밝혀라"를 걸고 사람이 한 번이라도
"그거 아니야"라고 하는지 센다. 코드 변경 0, 되돌리기 즉시.

## 7. 지표

**North Star: 주당 사람이 판정한 기억 건수** (확인 또는 정정).

세는 이유는 이것이 유일하게 **주입이 일어나고 + 사람이 반응해야** 올라가는 수이기 때문이다.
DAU는 이 제품에서 거짓말을 한다. 사람이 앱을 안 여는 것이 성공이다.

| 입력 지표 | 지금 값 |
|---|---:|
| 주입된 기억 (recall) | 주당 수백 |
| 그중 출처가 **사람에게** 보인 것 | 0 (모델에게는 제목+id가 전부 감) |
| 사람이 판정한 것 | **주당 0에 가까움** |
| 손대지 않은 신호 | 160 |

HEART에서 **Task success 하나만** 본다. Engagement를 보면 "앱을 더 자주 열게 하자"로
붕괴하고, 그건 이 제품이 파는 것의 반대다.

## 8. 윤리 점검

- **해악:** 자동 주입은 사람이 모르는 사이에 자기 과거를 대화에 넣는다. 출처 노출은
  프라이버시 기능이기도 하다. 무엇이 들어갔는지 본인이 알아야 한다
- **접근:** 타깃이 비개발자인데 오늘 유일하게 작동하는 경로(`recall` 훅)는
  Claude Code 설정을 요구한다. 이 모순이 남아 있다
- **장기 유인:** 정정이 대화에서 끝나면 앱을 열 이유는 더 줄어든다. 그것을 실패로 세지 않도록
  지표를 North Star 하나로 묶어 둔다

## 9. 이 문서가 뒤집는 것

`2026-08-28-what-memex-is.md`의 3번 **"데스크탑 앱은 잘못 기억한 것을 바로잡는 곳"** 은
살아 있되 **유일한 문이 아니다.** 정정의 1차 경로는 대화이고, 앱은 감사와 복구다.

같은 문서의 4번(비개발자 타깃, 앱이 설치 경로)은 그대로다. 다만 앱이 제품의 전부라는
읽기는 로그가 지지하지 않는다.
