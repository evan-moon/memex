# memex 데스크톱 앱은 무엇인가 — 기능 정의

> `2026-08-29-app-chat-design.md`가 **왜 대화창인가**와 **Electron이 무엇을 져야 하는가**를
> 정했다. 이 문서는 그 다음 질문에 답한다: **앱이 가진 기능이 정확히 무엇이고, 어디까지가
> 아직 없는가.**
>
> 앞 문서를 쓴 뒤 온보딩을 격리 환경에서 실제로 돌려봤고, **세 곳이 고장나 있었다.** 1절이
> 그 기록이다. 그리고 대화창은 아직 **코드에 한 줄도 없다** — 3절이 그것을 정의한다.

## 0. 이 문서가 정하는 것

| | 상태 |
|---|---|
| 1. 온보딩 (설치·로그인·등록) | **있다.** 고장나 있었고 고쳤다 (1절) |
| 2. 첫 실행 경로 | **없다.** 온보딩 화면에 도달할 방법이 없다 (2절) |
| 3. 대화창 | **없다.** 이 문서가 정의한다 (3·4·5절) |
| 4. 읽는 화면들 | 있다. 이 문서는 건드리지 않는다 |
| 5. 배포 | CI의 공증된 dmg는 **뜬다**. 로컬 `package:mac`이 만든 것은 안 떴다 (1절) |

## 1. 온보딩 — 되는 것과 고장나 있던 것

전제부터 확인했다. 격리된 HOME에 `install.sh`를 비-TTY로 돌리고, 빈 볼트로 API를 띄워
첫 실행 상태를 화면으로 봤다.

**설계 문서 9절의 표는 전부 맞다.** `claude auth status --json`이 `loggedIn`·`authMethod`·
`subscriptionType`을 주고, `findClaudeBinary`가 PATH 없이(=Finder 실행 조건) 바이너리를 찾고,
설치 스크립트가 비-TTY에서 완주하고, `claude auth login`이 로컬 콜백 리스너를 열어
**stdin 없이 완료된다** — `login.ts`가 `stdio: ['ignore', ...]`인 것이 맞다.

고장나 있던 세 곳은 전부 **"테스트가 통과하는데 실제로는 안 되는"** 종류였다.

### 1-1. `yarn dev:ui`에서 모든 쓰기가 403

`server.ts:643`이 `Origin !== Host`인 쓰기를 거부하는데, Vite 프록시가 브라우저의 Origin을
그대로 넘겼다. **온보딩 버튼이 한 번도 실제로 눌려본 적이 없는 이유다.** 화면은 만들어졌고
API도 맞았는데 둘을 잇는 개발 경로만 끊겨 있었다.

프록시가 Origin을 target으로 다시 쓰게 고쳤다. 그 뒤 `missing → 설치 → logged-out`이 앱을
통해 처음으로 통과했다.

> 패키징된 앱은 렌더러가 API와 같은 오리진이므로 이 버그가 없다. **개발 경로에만 있는
> 버그가 개발자가 기능을 검증할 유일한 경로를 막고 있었다.**

### 1-2. 로그인 버튼을 눌러도 브라우저가 열리지 않았다

`claude auth login`은 URL을 **OSC 8 터미널 하이퍼링크**로 감싸 출력한다 — `ESC]8;;URL BEL
URL ESC]8;;BEL`. TERM 유무와 무관하다. `login.ts`의 `/https:\/\/[^\s"'<>]+/`는 이스케이프를
제외하지 않으므로 **URL·BEL·URL을 통째로 삼켜 450자짜리 문자열**을 만들었고, 그것이 `open`에
넘어갔다. 화면은 "기다리는 중"이라고 말하고 아무 일도 일어나지 않는다.

제어문자를 제외하고(`\p{Cc}`), 청크 경계에서 잘린 URL을 열지 않도록 종결 문자를 기다리게
고쳤다. 회귀 테스트 둘 다 옛 코드에서 실패하는 것을 확인했다.

### 1-3. 패키징된 앱이 실행되지 않는다

`release/`의 앱을 띄우니 `ERR_DLOPEN_FAILED`, **NODE_MODULE_VERSION 127 vs 130.**

`package:mac`이 `yarn workspace @memex/desktop package; yarn native:node`였다. 앞에
`native:electron`이 없어서 electron-builder가 **Node ABI 바이너리를 그대로 번들에 넣는다.**
`npmRebuild: true`는 워크스페이스로 호이스팅된 모듈을 다시 빌드하지 못했다.

`native:electron`을 앞에 넣어 고쳤다. 올바른 `.node`를 넣으니 앱이 뜨고 실제 볼트
(노트 1404개)를 서빙한다.

### CI는 멀쩡했다 — 확인함

처음에는 **CI도 같은 순서라 공증된 dmg도 안 열릴 것**이라고 적었다. **틀렸다.** 수정 전
마지막 성공 실행의 아티팩트를 받아 마운트하고 실행해봤다. `spctl`이 `Notarized Developer
ID`로 통과하고, 앱이 뜨고, 볼트를 서빙한다.

차이는 `.forge-meta`다. `@electron/rebuild`는 마지막으로 어떤 ABI로 빌드했는지를
`build/Release/.forge-meta`에 적어두고, 기록이 맞으면 일을 건너뛴다. **`native-abi.mjs`는
바이너리만 바꾸고 그 기록은 건드리지 않는다.** 그래서 로컬 트리에서는:

```
package:mac  →  electron-builder가 130으로 리빌드, .forge-meta = 130
             →  끝에 native:node가 바이너리를 127로 되돌림. .forge-meta는 여전히 130
다음 package:mac  →  rebuild가 기록을 믿고 건너뜀 → 127짜리가 번들에 들어감
```

**스크립트 자신의 뒷정리가 다음 빌드를 망친다.** CI에는 `yarn install`이 만든 새 트리라
거짓 기록이 없고, 그래서 rebuild가 실제로 돌아 정상 dmg가 나왔다.

`native-abi.mjs`가 스왑할 때 그 기록을 지우게 했다. 이게 근본 수정이고, 패키징 앞의
`native:electron`은 그 위의 안전벨트다.

### 그래도 실행 검사는 넣었다

`codesign --verify`도 `spctl`도 **앱이 실행되는지는 묻지 않는다.** 이번에는 CI가 멀쩡했지만,
켜자마자 죽는 dmg가 모든 검사를 통과할 수 있다는 것은 그대로다 — 로컬 빌드가 실제로 그랬다.

`ELECTRON_RUN_AS_NODE=1`로 번들 안의 `.node`를 Electron 자신의 런타임에 로드해보는 것은
**디스플레이가 필요 없다.** 헤드리스 러너가 사람 대신 할 수 있는 유일한 실행 검사이고,
워크플로에 넣었다. 통과하는 것을 확인했다(run 33247419769).

> 이 세 개의 공통점: **768개 테스트가 통과하는 상태에서 전부 살아 있었다.** 앞 문서가
> "패키징된 것을 실제로 띄워라"라고 남긴 이유가 그대로 반복됐다.

## 2. 첫 실행 — 게이트가 없다

빈 볼트로 앱을 처음 켜면 `/`의 Overview가 나온다:

> **Nothing to do today.** All done.

그리고 0이 늘어선 카드들. `/connect`로 가는 길은 **사이드바 맨 아래 링크 하나**뿐이고,
Overview에는 빈 상태 안내가 없다. `App.tsx`의 라우팅은 상태와 무관하게 `/`를 Overview로
보낸다.

온보딩 화면 자체는 잘 만들어져 있다 — 1·2·3단계, 282MB 모델 카드, 실패 시 수동 안내.
**도달할 방법이 없을 뿐이다.** 컨셉 4번(대상은 비개발자)에서 이건 기능이 없는 것과 같다.

### 결정 — 준비 상태가 라우팅을 정한다

`/api/ready`가 세 불리언을 준다. 그런데 **셋이 같은 무게가 아니다.**

| | 없으면 무엇이 안 되나 | 게이트인가 |
|---|---|---|
| 모델 (282MB) | 검색·정정 노트. **register 값 교정은 된다** | 검색을 쓰려 할 때 |
| Claude Code 로그인 | 대화창 전부 | **그렇다** |
| MCP 등록 | *다른* 앱의 Claude가 memex에 못 닿음 | **아니다** |

MCP 등록이 게이트가 아니라는 게 핵심이다. 대화창은 `packages/llm`이 `claude -p`를 직접
부르므로 **memex MCP 서버를 전혀 쓰지 않는다**(`claude-code.ts`가 `--strict-mcp-config`로
비운다). 등록은 *다른 세션의 Claude*를 위한 것이고, 앱 자신은 등록 없이 완전히 동작한다.
3단계를 통과 조건으로 걸면 **필요 없는 것을 필수처럼 보이게 만든다.**

그래서:

- 로그인이 안 됐으면 `/`가 `/connect`로 간다. 건너뛸 수 있고, 건너뛰면 다시 묻지 않는다
- 모델은 게이트가 아니다. 받는 동안 앱을 쓸 수 있고, **검색이 기다린다** (앞 문서 6절)
- 등록은 `연결` 화면의 3단계로 남되 첫 실행을 막지 않는다
- **Overview의 빈 상태가 "All done"이라고 말하면 안 된다.** 아무것도 안 한 상태와 다 한
  상태가 같은 문장을 쓰고 있다

## 3. 대화창

### 3-1. 범위 — 독립 대화창이다

> 앞 문서 8절 3번은 `지금 참인 것` 화면 **안의 한 줄**부터 시작하자고 했다. 그러면 4절의
> "대상이 이미 화면에 있고"가 자동 충족되기 때문이다. **이 결정은 뒤집혔다** — 독립
> 대화창으로 간다. 대신 그 안전성을 공짜로 얻지 못하므로 4절 표가 그만큼 보수적이 된다.

`/chat`이 사이드바의 항목이 된다. 그리고 노트·register 화면에서 **대상을 실은 채** 대화창을
여는 입구를 둔다 — 같은 문장이라도 대상이 정해진 채로 오면 확인 단계를 건너뛸 수 있다
(4절). 인라인 입력을 안 만드는 것이지, 맥락을 버리는 것이 아니다.

### 3-2. 한 턴의 모양

`packages/llm`은 **프롬프트 하나 → 텍스트 하나**다. 툴 호출도 대화 상태도 없다. 그래서
대화창은 모델에게 툴을 주는 대신 **자기가 오케스트레이션한다:**

```
1. 후보 찾기   앱이 semanticSearch로 후보를 모은다 (모델 없음, 결정적)
2. 해석        LLM 한 번: 사람의 문장 + 후보 → 구조화된 계획(JSON)
3. 되말하기    계획을 사람의 문장으로 렌더링
4. 확인        4절 표가 정하는 대로 (즉시 / 버튼)
5. 실행        앱이 @memex/core 함수를 직접 부른다
```

**모델은 볼트에서 노트를 고르지 않는다.** 앱이 후보 집합을 주고, 모델은 문장을 그 집합
위에 얹기만 한다. 이것이 앞 문서 4절이 걱정한 "모델이 대상을 고른다"를 좁힌다 — 고르긴
하지만 앱이 보여준 것 중에서만 고른다.

```
apps/desktop/chat/   또는 apps/cli/src/services/chat/
  turn.ts        위 5단계
  plan.ts        해석 결과 타입 + 방어적 JSON 파싱
  render.ts      계획·결과 → 사람의 문장
  errors.ts      5절의 여덟 가지
```

두는 위치는 하나만 정하면 된다: **`memex ui`와 앱이 같은 서버를 쓰므로**(`host.ts`의
`createUiDeps`) 대화창도 CLI 쪽 서비스에 두는 것이 일관된다. `apps/desktop`에 두면 웹
UI에서 대화가 사라진다.

### 3-3. MCP 지침은 새어들지 않는다 — 확인함

앞 문서 3절이 걱정한 것: MCP 표면을 재사용하면 *"call save_note **without asking the
user**"*가 딸려와 대화창이 기록기가 된다.

`claude-code.ts`의 `NO_TOOLS = ['--strict-mcp-config', '--mcp-config', '{"mcpServers":{}}']`가
**memex MCP 서버를 통째로 비운다.** 그 지침은 도달하지 않는다. 이 걱정은 이미 닫혀 있다.

**다른 것이 새어든다** — 6절.

## 4. 무엇을 쓸 수 있나

Evan의 결정: **교정 + 새 노트 + rule 승인.** 삭제는 없다.

| 연산 | 확인 | 왜 |
|---|---|---|
| register 값, 기존 predicate, **대상을 싣고 연 대화** | 즉시 + 한 줄 되말하기 | 모호함이 없다 |
| register 값, 기존 predicate, 빈 대화창 | **확인** | 모델이 subject를 골랐다 |
| register 값, **새 predicate** | **확인** | `register.ts:101`이 유사 키를 합치지 않는다. 되말하기는 fork가 생긴 뒤에 온다 |
| `past` 정정 | **확인** | 새 노트 + `amends` 필수. 원문은 고치지 않는다 |
| **새 노트** | **확인** | 폴더·layer·tags를 보여주고 누르면 저장 |
| `rule` **승인·거부** | **확인** | provisional인 것만. 대화가 새 rule을 approved로 만들 수 없다 |
| `delete_note` | — | **대화창에 노출하지 않는다** |

두 줄을 덧붙인다.

**되돌리기는 되돌리기가 아니다.** `register.ts:157`은 append-only다. 이전 값을 다시 쓰면
tip은 돌아오지만 잘못된 이벤트는 회수되지 않고, 되돌린 행위가 사람 이름으로 하나 더
기록된다. **화면이 "되돌렸어요"가 아니라 "이전 값으로 다시 썼어요"라고 말해야 한다.**

**rule 승인이 대화에 있어도 컨셉 3번은 지켜진다.** 사람이 rule 전문을 보고 누르는 것이
사람의 승인이다. 금지되는 것은 *문장 하나가 provisional을 건너뛰고 approved를 만드는 것*
이다. 대화창은 이미 있는 provisional을 꺼내 보여주고 승인받을 수 있을 뿐이다.

## 5. 에러 — 여덟 가지가 각각 다른 문장이어야 한다

지금 정규화되는 것은 `ENOENT → not-installed` 하나뿐이다(`claude-code.ts`).

| | 화면이 말해야 하는 것 |
|---|---|
| CLI 없음 | 설치 화면으로 (`연결` 1단계) |
| CLI 로그아웃 | 로그인 화면으로 (2단계) |
| 구독 거부 / 한도 | 요금제 문제지 memex 문제가 아니라는 것 |
| 모델 거부 | 다른 모델로 다시 |
| 잘못된 계획 (JSON 파싱 실패) | 다시 말해달라고. **아무것도 쓰지 않았다는 것** |
| 중단됨 | 사람이 취소했다. 쓰지 않았다 |
| 부분 쓰기 | **무엇이 쓰였고 무엇이 안 쓰였는지** |
| 오프라인 | register 교정은 되고 검색은 안 된다 |

마지막 셋이 중요하다. 교정 도구에서 **"썼는지 안 썼는지 모르겠는 상태"가 가장 나쁜 상태**다.

## 6. 프롬프트 위생 — `CLAUDE.md`가 새어든다 (미해결)

`claude -p`는 MCP를 비워도 **사용자 레벨 `~/.claude/CLAUDE.md`를 자동으로 읽는다.** 확인했다:
중립 디렉토리에서 물었더니 모델이 Evan의 한국어 코드 스타일 가이드를 갖고 있다고 답했고,
호출당 **~23.6k 토큰**(cache_read 13.6k + creation 10k)이 붙었다.

이건 대화창만의 문제가 아니다. `draft`·`conflicts`·`claim-extract`가 **지금도** 매 호출마다
관계없는 컨텍스트를 지고 있다.

- `--bare`는 CLAUDE.md 자동 발견을 끄지만 **OAuth·키체인을 읽지 않는다** — `ANTHROPIC_API_KEY`
  전용이라 구독 경로에서 쓸 수 없다
- `--system-prompt`로 교체해도 안 빠진다 (확인함, 여전히 17k)
- `HOME`을 바꾸면 자격증명도 같이 사라진다

**비개발자에게 배포하면 이건 예측 불가가 된다.** 그 사람의 `CLAUDE.md`에 무엇이 들어 있든
memex의 추론 프롬프트가 그것을 물려받는다. 지금은 열린 제약으로 남긴다.

## 7. 안 만드는 것

앞 문서 7절을 그대로 유지한다: 대화 히스토리 영속화, 멀티 provider 선택 UI, 앱 안 자동
업데이트, 스트리밍 토큰 렌더링. 여기에 하나 더 — **대화창의 삭제.**

## 8. 착수 순서

1. **첫 실행 게이트** (2절). 대화창 없이도 앱이 비개발자에게 켜지는 최소 조건이다
2. **Overview 빈 상태** — "All done"이 거짓말을 하지 않게
3. **`turn.ts` + `plan.ts`** — 후보 찾기 → 해석 → 계획. **화면 없이 테스트 가능하다**
4. **`render.ts` + `errors.ts`** — 5절 여덟 가지
5. **`/chat` 화면**
6. 배포 게이트 (9절)

3번을 화면보다 먼저 두는 이유는 앞 문서와 같다: **계획이 맞는지는 대화창 없이 검증된다.**

## 9. 배포 게이트
