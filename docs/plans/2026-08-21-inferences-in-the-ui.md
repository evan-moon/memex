# inference를 화면에 어떻게 올릴까 — 제안

## 지금 뭐가 있나 (실측)

가설 2개. **둘 다 stale이고, UI 어디에도 나오지 않는다.**

```
#2  6년에 걸친 '함수형 = 부작용 속 안전한 합성' 자기주도 커리큘럼
    근거 6개 · confidence 0.78 · claude-opus-4-8 · stale
#3  에세이를 관통하는 인식론 엔진: 인지과학적 환원 × 맥락주의
    근거 7개 · confidence 0.75 · claude-opus-4-8 · stale
```

세 가지가 설계를 좌우한다.

1. **작지 않다.** 요약이 300자가 넘고 근거가 6~7개다. 배지로 붙일 물건이 아니라 읽을 물건이다.
2. **검색에 안 나온다** — 의도된 것이다(model collapse 방지). 그래서 **의도적으로 만든 문 말고는 도달 경로가 없다.**
3. **근거가 태그를 공유하지 않을 수 있다.** #2는 `Functional Programming`을 5/6이 공유하지만, **#3은 3개 이상 공유하는 태그가 하나도 없다.** 태그가 잇지 못한 것을 찾아낸 게 그 가설의 값어치다 — 주제 화면에만 걸면 가장 값진 가설이 어디에도 안 나온다.

## 프레임 — 가설은 기계가 쓴 투영이다

[[state를 "선언된 투영"으로]]에서 정리한 구조가 그대로 적용된다.

| | state 노트 | inference |
|---|---|---|
| 쓴 주체 | 사람 | 모델 |
| 근거 | `derives_from` + 본문 해시 | `inference_evidence` + 본문 해시 |
| 낡음 | 해시·정정 비교 | 해시 비교 |
| 검색 | 나온다 | 나오지 않는다 |
| 권위 | 판단 | 가설 |

**구조가 같고 저자가 다르다.** 오늘 넣은 person/agent 축이 이미 그 구분의 이름이다. 그러니 가설을 별개 세계로 만들 이유가 없다 — 사람의 투영이 사는 자리에, 가설이라고 표시해서 놓으면 된다.

## 배치

### 1. 노트 화면 — 1순위

백링크 옆에 **"이 노트를 근거로 삼은 가설"**. 근거 노트 하나하나가 문이 된다.

**#3처럼 태그를 공유하지 않는 가설에 유일하게 작동하는 앵커다.** 에세이 7개 중 아무거나 열면 "이 글은 어떤 가설의 근거야"가 보인다.

### 2. 주제 화면 — 근거가 뭉칠 때만

지금 `hidden_arc` 신호를 "💡 아직 엮이지 않은 흐름"으로 띄우는 자리가 있다. **가설은 그 arc가 mint된 결과물이다.** 같은 자리에 놓되, 신호는 "여기 뭔가 있다"이고 가설은 "이거다"라는 차이를 표시한다.

### 3. `/inference/:id` — 읽는 자리

새 라우트를 하나 만든다. 300자 요약 + 근거 6~7개 + 각 근거의 상태(그대로/바뀜/사라짐) + 모델·confidence + mint 시점 프롬프트 스냅샷. **"AI가 왜 그렇게 생각했지?"에 답하는 화면** — #1437의 Verifiability가 가장 진하게 필요한 곳이다.

### 4. 홈 "손볼 것" — 낡은 가설

`낡은 가설  2  ›` 한 줄. 지금 깨진 링크·태그와 같은 취급.

### 하지 않는 것

**가설 목록 화면을 만들지 않는다.** 신호와 같은 규칙이다 — 처리할 큐가 아니라 맥락 속에서 만나야 한다. `/inference/:id`는 하나를 읽는 자리지 전부를 훑는 자리가 아니다.

## 동사

| | 무엇 | 비용 |
|---|---|---|
| **폐기** | `status = 'archived'` | 없음 |
| **노트로 승격** | 가설을 state 노트로 만들고 **같은 근거를 `derives_from`으로 선언** | 없음 |
| **다시 뽑기** | 근거를 다시 읽혀 재합성 | LLM 호출 |

**승격이 핵심이다.** 기계가 제안하고, 사람이 읽고, 받아들이면 그 순간 **검색 가능하고 권위 있는 기억이 된다.** 오늘 만든 근거 선언이 그대로 이어져서, 승격된 노트는 처음부터 자기 출처를 안다. CQRS로 보면 이게 read model이 확정되는 지점이다.

model collapse 위험은 여기서 닫힌다: 승격된 노트의 `derives_from`은 **원래의 1차 근거를 가리키지 가설을 가리키지 않는다.** 가설은 검색에 안 나오므로 다음 합성의 입력이 될 수 없고, 승격본은 사람이 손을 댄 판단이다.

**다시 뽑기는 결정이 필요하다.** memex는 LLM을 부르지 않는다는 원칙이 있지만(#1437), 이미 예외가 하나 있다 — stale state 초안이 `claude -p`를 shell out한다. 같은 방식으로 열지, 아니면 재합성은 대화(MCP `mint_inference`)에만 남길지.

## 단계

1. `/api/note/:id`에 "이 노트를 근거로 삼은 가설" + 노트 화면 섹션
2. `/inference/:id` 읽는 화면 (근거 상태·프롬프트 스냅샷 포함)
3. 홈 "손볼 것"에 낡은 가설 한 줄
4. 폐기 / 노트로 승격
5. 주제 화면 카드 (arc와 나란히)
6. (결정 필요) 다시 뽑기
