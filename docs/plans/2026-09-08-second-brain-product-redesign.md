# memex 제품 재설계 제안

상태: 논의용 제안. 구현 지시나 기존 운영 정책의 변경 승인이 아니다.
날짜: 2026-09-08

후속 상세 설계: [경험 설계](2026-09-08-memex-experience-spec.md) · [데이터와 동작 계약](2026-09-08-memex-domain-contract.md) · [Claude Code 인수인계](2026-09-08-memex-implementation-handoff.md). 제품 정의는 이 문서, 구체적인 화면/저장/검증 계약은 후속 문서를 기준으로 읽는다.

## 1. 출발점과 증거

사용자는 memex를 개인 기억 기반으로 쓰면서, Obsidian 대신 자료를 읽고 글을 쓰는 앱으로도 사용하고 싶다고 밝혔다. 글쓰기 전용 제품으로 축소하는 것은 원하지 않는다. 이 요구를 이번 설계의 기준으로 삼는다.

현재 코드에서 확인한 것:

- `apps/ui/src/Sidebar.tsx`: 확인하기·찾기·고치기가 주 내비게이션이고 노트 트리가 붙는다.
- `apps/ui/src/Overview.tsx`: 기존 볼트는 확인 카드, 빈 볼트는 설정으로 안내한다.
- `apps/ui/src/onboarding.ts`: AI 엔진 연결이 온보딩 완료의 필수 조건이다.
- `apps/ui/src/screens.tsx`: 문서 조회·검색·신규 작성 화면은 이미 존재한다.
- `apps/cli/src/services/chat/plan.ts`: 검색·읽기·스킬 사용·신규 문서·수정 계획이 있으나 교정 도구라는 전제를 갖는다.
- `apps/mcp/src/tools/get-note.ts`, `search-notes.ts`: 사람이 확인하거나 폐기한 주장의 상태를 전달하는 기능이 존재한다.
- `apps/ui/src/Review.tsx`: 틀렸다고 표시하는 동작은 새 값을 받는 정정으로 연결되지 않는다.
- `CLAUDE.md`: 사람은 기억을 고칠 때만 쓴다는 정책이 명시돼 있어 새 요구와 충돌한다.

기존 사용 분석은 한 볼트의 과거 기록이다. 앱 조회 비중으로 글쓰기 수요가 없다고 결론 내리지 않는다. 이번에는 앱 실사용 관찰이나 최신 로그 재측정을 하지 않았다. 새 사용자 수요·시장성·유료 전환은 미검증이다.

## 2. 제품 정의와 선택

**memex는 내가 쌓은 자료·경험·생각을 사람과 AI가 함께 활용하여 다음 글과 일을 이어가는 개인 Second Brain이다.**

핵심 순환: 남기기 → 찾고 이해하기 → 쓰고 결정하기 → 결과를 다시 남기기.

세 가지 방향을 비교한다.

| 방향 | 이점 | 한계 |
|---|---|---|
| 기억 인프라 중심 | 외부 AI에서 가치를 빠르게 전달 | 직접 읽고 쓰는 사용자 요구를 충족하지 못함 |
| AI 글쓰기 앱 중심 | 핵심 화면과 작업이 명확 | 개인 기억·프로젝트 의사결정의 가치를 축소 |
| 개인 지식 작업 공간 + 공통 기억 기반 | 사용자 요구 두 가지를 함께 충족 | 범위가 커지므로 첫 완결 흐름을 제한해야 함 |

세 번째를 제안한다. 첫 사용자는 기존 Markdown 자료와 AI 작업 습관이 있는 개인이다. 일반 비개발자 전체로의 확장은 설치와 첫 가치가 검증된 뒤 다룬다. 팀 협업·실시간 공동 편집·공개 발행·플러그인 생태계·지식 그래프 전용 화면은 첫 범위에서 제외한다.

## 3. 표면별 책임

| 표면 | 책임 | 완료 기준 |
|---|---|---|
| 데스크탑 | 직접 읽기·작성·자료 비교·AI 협업·기억과 접근 관리 | 자료에서 실제 원고/계획까지 앱에서 완결 |
| MCP | 외부 AI가 검색·출처 확인·기억 저장·문서 변경에 참여 | 앱 밖의 작업도 같은 문서와 변경 이력으로 연결 |
| CLI | 진단·일괄 가져오기·색인 복구·자동화 | 앱과 MCP의 정책을 그대로 사용하며 복구 가능 |
| 공통 도메인 서비스 | 저장·검색·버전·출처·정정·권한 규칙 | 어느 표면으로 접근해도 의미와 결과가 동일 |

데스크탑을 종료해도 MCP 사용이 가능해야 한다. 공유 서비스는 논리적 경계이며, 새 상시 서버나 데몬 추가를 전제로 하지 않는다. CLI에 있는 재사용 서비스는 점진적으로 분리하며 기존 명령과 MCP 호환성을 먼저 유지한다.

## 4. 정보 모델: 문서와 기억을 구분

문서는 사람이 다루는 원본이다. 기억은 문서·대화에서 추출하여 이후 작업에 쓰는 주장이다. 같은 문서에 과거 사건과 현재 사실이 함께 있을 수 있다. 문서 종류로 사실의 유효기간을 결정하지 않는다.

| 개념 | 예 | 규칙 |
|---|---|---|
| 문서 | 메모·참고 자료·초안·완성 글 | 사용자가 자유롭게 편집, 원본과 버전 보존 |
| 기억 | 현재 출시일·결정 이유·선호 | 근거 문서/구절/버전, 적용 범위, 변경 이력 보유 |
| 지침 | 글쓰기 스킬·코딩 규칙 | 작업별 선택과 범위 지정, 읽었다고 자동 실행하지 않음 |

문서에는 출처(사람/외부/AI), 작성 상태, 선택적인 종류를 둔다. 처음부터 분류 입력을 요구하지 않는다. 문서의 게시 상태나 AI 수정 수락은 그 안의 모든 주장을 현재 사실로 승인한 것과 다르다.

`past/state/rule`은 기존 호환 메타데이터로 유지한다. 기존 노트는 먼저 문서로 접근 가능하게 만들고, 기억·지침으로의 연결은 명시적 메타데이터와 확인 가능한 근거에 따라 점진적으로 만든다. 과거 기록의 보존은 버전/이력으로 해결하고, 글을 수정할 때 정정 노트를 새로 만들도록 강제하지 않는다.

기존 주장 추출·register·정정 관계는 기억 기반으로 재사용한다. 사용자 화면에 이 구현 이름들을 독립 메뉴로 늘리지 않는다. 원문 변경 시 파생 기억의 근거 변경을 표시하며, 이를 사실이 거짓이 됐다는 판정으로 취급하지 않는다.

## 5. 앱 구성

기본 내비게이션: 홈 / 라이브러리 / 검색. 아래에 기억 / 설정을 둔다. 새 문서는 어디서든 바로 만들 수 있다. 지침은 라이브러리의 종류/필터로 접근한다. 초기에는 별도의 프로젝트 객체 없이 기존 폴더와 문서 링크를 재사용한다.

- 홈: 작업 중인 문서, 최근 작업, 관련된 중요한 변경. 빈 상태에서는 새 문서 또는 기존 폴더 연결. 확인 카드를 기본 업무로 배정하지 않는다.
- 라이브러리: 기존 폴더 구조를 유지하면서 모든 문서·자료·지침에 접근. 여러 문서를 탭으로 열고 필요할 때 나란히 읽는다.
- 검색: 키워드/의미 검색, 맞은 구절, 출처, 현재성, 필터. 답변을 생성하더라도 원문 접근을 남긴다.
- 문서 작업 화면: 가운데 편집기, 옆에 선택적으로 참고 자료/AI 패널. 선택 문장·현재 문서·지정 자료를 AI 맥락으로 명시한다. AI 패널을 닫아도 완전한 읽기/쓰기 도구여야 한다.
- 기억: 주제별 현재 정보와 근거·이력. 충돌·정정은 해당 주제와 문서에서도 접근 가능하다.
- 설정: 볼트, 연결 앱, AI 제공자, 접근 범위, 백업/복구, 색인 상태. 유지보수 화면은 여기에 모은다.

## 6. 세 가지 핵심 저니

### A. 자료로 글 쓰기 — 첫 번째 개발 흐름

기존 폴더를 연결하거나 새 문서를 만든다 → 몇 줄을 직접 쓴다 → 관련 자료를 검색한다 → 참고할 구절과 지침을 선택한다 → 개요/문단 제안을 받는다 → 일부를 적용하고 직접 수정한다 → 닫았다 열어 이어 쓴다.

완료 기준: 실제 글 한 편을 만들며 원문 접근, 선택 범위 수정, 자동 저장, 재진입, 변경 취소가 모두 작동한다. 신규 사용자는 AI 로그인 없이도 문서를 만들고 읽을 수 있어야 한다. AI와 검색 모델 준비는 해당 기능을 쓸 때 진행 상태와 대안을 제공한다.

### B. 외부 AI에서 일 이어가기

외부 대화에서 지난 결정을 묻는다 → MCP가 근거와 현재 상태를 반환한다 → AI가 출처를 밝히고 작업한다 → 새 결정이나 문서 변경을 남긴다 → 앱에서 동일한 결과와 이력을 확인한다.

완료 기준: 앱 재시작/수동 재색인 없이 변경을 확인하고, 이전 버전을 대상으로 한 쓰기는 충돌을 알린다. 연결 상태 확인과 실제 검색/저장 성공을 구분한다.

### C. 틀린 기억 바로잡기

대화 또는 앱에서 오류를 발견한다 → 해당 근거를 확인한다 → 올바른 값 또는 더는 유효하지 않다는 판정을 남긴다 → 과거와 현재의 관계를 저장한다 → 다음 조회에서 정정을 확인한다.

완료 기준: 원인을 특정할 수 있으면 앱 이동 없이 완료. 여러 기억이 충돌하면 앱에서 비교. 새 값을 모르면 폐기/미확정으로 둘 수 있어야 한다. 테스트에서는 이후 조회 결과를 검증하며, 외부 모델이 모든 답에서 준수한다고 보장하지 않는다.

## 7. AI 쓰기와 신뢰 계약

- 사람이 입력한 편집은 즉시 자동 저장하고 버전 복구를 제공한다.
- 새 AI 초안은 기존 문서를 덮지 않고 제안 또는 새 초안으로 생성한다.
- 기존 글 수정은 요청된 범위에 한정한다. 변경 미리보기와 적용/되돌리기를 제공한다. 사용자가 명확히 지정한 자동 적용 정책이 있으면 따른다.
- 자동 기억 저장은 사용자 설정 범위에서 허용하되, AI 추출과 사용자 직접 진술을 구분한다.
- 지침은 어떤 작업에 적용됐는지 보인다. 외부 인용문이나 초안을 지침으로 실행하지 않는다.
- 로컬 보관과 외부 모델 전달을 구분한다. AI 요청에는 사용되는 문서 범위와 연결 제공자를 확인할 수 있게 한다.
- 외부 편집과 앱/에이전트의 동시 수정은 문서 버전으로 감지한다. 오래된 버전의 전체 덮어쓰기를 막고 비교/재시도를 제공한다.

## 8. 기존 기능 처리

| 현재 자산 | 처리 |
|---|---|
| Markdown, 폴더, 편집기, 탭, 이력, 휴지통 | 앱 기반으로 유지, 실제 문서 작업 검증 |
| 의미/전문 검색, 링크, 근거 | 문서 작업과 외부 조회에 공통 사용 |
| 고치기 채팅 | 현재 문서를 읽고 쓰는 AI 패널로 확장 |
| 홈 확인 덱 | 기억 화면 및 관련 문서의 판단 요청으로 이동 |
| register, claims, 정정 흐름 | 기억의 근거/현재성/변경 이력으로 통합 |
| signals, inferences, flashback | 현재 작업에 관련된 제안으로 노출, 별도 백로그 확대 중단 |
| tags tidy, repair, 재색인 | 설정의 관리 작업과 CLI 진단에 배치 |
| 기존 CLI/MCP 계약 | 유지하며 공통 서비스로 점진 이전 |

## 9. 실행 순서와 통과 조건

1. 제품 계약 정리: 이 제안을 검토한 뒤 README, CLAUDE.md, 온보딩의 타깃·직접 쓰기·표면 역할을 일치시킨다. 과거 문서는 삭제하지 않고 대체 관계를 적는다. 이번 문서 작성만으로 기존 정책은 변경하지 않는다.
2. 읽고 쓰기 완결: AI 연결 없이 시작, 빈 상태, 원고 재진입, 자료 동시 열람, 자동 저장/복구, 기존 폴더 호환. 사용자의 실제 볼트와 글 한 편으로 검증한다. 링크와 알려진 문서 형식의 호환 범위를 먼저 기록한다.
3. 근거 기반 AI 협업: 선택 자료/지침, 범위 지정 수정, 출처, 변경 적용과 취소. 글쓰기와 프로젝트 계획 수정 각각 한 건을 완결한다.
4. 표면 간 일관성: 동일 서비스와 문서 버전, MCP 변경 반영, 정정 후 조회. CLI/UI/MCP에서 동일한 사례로 읽기·수정·충돌·복구를 검증한다. 위험한 동시 쓰기 방지는 2~3단계부터 필요한 만큼 먼저 적용한다.
5. 발견 경험: 반복 사용 관찰 후 관련 기억·변화·연결 제안의 적합성을 개선한다. 그래프나 알림부터 만들지 않는다.

개발 항목은 한 저니 안에서 설계·구현·검증한다. DB 전체 개편과 화면 전체 교체를 별도 대형 선행 작업으로 만들지 않는다. 마이그레이션은 샘플 볼트와 복원 가능한 백업으로 검증하며, 기존 파일을 일괄 재분류하지 않는다.

## 10. 검증과 아직 결정하지 않은 것

초기 1~2주 사용 관찰은 시장 검증이 아니라 개인 사용 흐름 검증이다. 실제 원고 한 편, 외부 AI 작업 한 건, 기억 정정 한 건에서 막히는 단계와 우회 작업을 기록한다.

주 결과 지표는 기존 자료를 실제로 활용해 글/계획/작업을 끝낸 횟수다. 단순 검색 호출 수를 재사용으로 세지 않는다. 초기에는 사용자 확인으로 측정하고, 보조 지표로 첫 문서 재진입 성공, 자료 찾는 시간, 정정 후 같은 오류의 재발, 충돌/유실 발생을 본다. 콘텐츠를 외부 분석으로 보내는 계측은 전제하지 않는다.

아직 미확정: 반드시 호환해야 할 기존 볼트 문법/첨부 형식, 가장 자주 쓰는 글 유형, 기본 AI 제공자, 다른 기기 동기화 필요성, 일반 사용자 타깃과 수익 모델. 가격·시장 비교 없이 유료화 가능성을 확정하지 않는다. 우선 검증할 가치는 개인 자료를 재설명하고 복사하는 부담을 줄여주는 지속성이다.

다음 설계 산출물은 홈·문서 작업 화면·기억 상세의 세 화면과, 저니 A의 상호작용 시제품이다. 코드 구현 전에 사용자의 실제 자료로 이 흐름을 검토한다.
