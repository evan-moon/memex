# 홈 = 지금 확인할 것 — 정보 구조 승인 요청

> 운영 계약 memex #2280 §2·§3에 따른 승인 요청서. 색·글꼴·애니메이션 전 단계이고,
> 승인 전에는 구현하지 않는다.

## §2. 사용자 Job

**누가 여는가.** 볼트 주인. 비개발자. 하루를 대화 안에서 보내고 앱은 평소 열지 않는다.

**무엇이 진입을 촉발하는가.** "AI가 뭔가 이상하게 안다"는 낌새, 또는 중요한 일을 맡기기 전의
점검. 브라우징 욕구가 아니다.

**어떤 결정을 내려야 하는가.** AI의 현재 믿음 중 근거가 흔들린 것들을 하나씩 보고,
**승인 · 수정 · 보류** 셋 중 하나를 고른다.

**끝나면 무엇이 달라지는가.** 흔들린 믿음이 정리되고, 다음 대화부터 AI가 교정된 기억을 쓴다.
그리고 "지금은 볼 것 없음"이라는 완료 감각을 얻는다.

**근거와 미검증.** 근거는 로그다 — 앱은 전체 읽기의 0.36%이고 하루만 열렸다
(`2026-09-04-who-actually-reads-memex.md`). **미검증인 것:** 사람이 이 큐를 실제로 소비할지,
그리고 세 개짜리 세션이 "끝냈다"는 감각을 주기에 충분한지.

## §3-0. 실측 — 오늘 이 볼트로 카드를 채울 수 있는가

계약은 각 항목이 네 가지를 한눈에 답하라고 한다. 지금 신호들이 그걸 들고 있는지 재봤다.

| 후보 | 개수 | 네 답을 들고 있나 |
|---|---:|---|
| **낡은 추론** (`inferences.status='stale'`) | **9** | **예** — 어느 근거가 어떻게 움직였는지 이름까지 |
| **근거가 정정된 state** | **4** | **예** — 어느 출처가 어느 정정으로 뒤집혔는지 |
| 승인 대기 rule | 0 | 예 (지금은 없음) |
| 믿음 충돌 | 0 | 예 (지금은 없음) |
| 낡았을 수 있는 state (추측) | 30 | **아니오** — "근처에 노트 3개가 쌓였다"까지가 전부 |
| 끊긴 링크 | 128 | **아니오** — 믿음 변화가 아님 |

**결론: 오늘 이 볼트의 세션은 13건이고, 계약이 말한 3~5개를 채운다.**
추측 기반 30건과 끊긴 링크 128건은 "지금 확인할 것"이 아니라 3순위(둘러보기)로 내린다.
계약의 우선순위 목록에 없는 종류이고, 네 답을 못 하기 때문이다.

**2번 섹션(최근 바뀐 믿음)의 이전/현재 값**은 DB에 없다. `note_changes`는 무엇이 바뀌었는지
*종류만* 2,423건 들고 있고 값은 없다. 다만 볼트가 git이고 `apps/cli/src/services/ui/history.ts`가
이미 `git log`와 리비전을 읽는다. **재료는 있다.**

## §3-2. 기본 행동 하나

**첫 항목을 처리한다.** 승인 · 수정 · 보류.

## §3-3. 정보 위계 3단계

| 단계 | 무엇 | 왜 |
|---|---|---|
| **1** | 지금 확인할 것 — 3~5개 | 사람만 할 수 있는 일. 화면을 연 이유 |
| **2** | 최근 바뀐 믿음 | 판단은 필요 없지만 알아야 하는 것 |
| **3** | 둘러보기 — 주제 · 검색 · 최근 · 통계 | 찾으러 왔을 때만 |

## §3-4. 제거하거나 낮출 것

| 지금 | 어디로 |
|---|---|
| "1,374개의 기록, 73개의 주제"가 제목 자리 | **3단계로.** 숫자는 다음 행동을 대신하지 못한다 |
| "새로 들어온 것" 폴더별 피드 | **삭제.** `projects`/`docs`/`(root)`는 저장 구조지 정신 모델이 아니다 |
| "오늘 할 일 9개 →" 작은 링크 | **1단계로 승격.** 이미 옳은 물건이었고 제일 작게 그려져 있었다 |
| 주제 스파크라인 | **3단계로.** 신뢰 보조 정보 |
| "오늘의 연결" | **3단계로.** 우연한 발견은 판단이 아니다 |

│  │   9월 2일 정정됐어요                                 │  │

**한 화면에 한 장만 편다.** 3~5개를 동시에 펼치면 그건 백로그다. 나머지는 아래 접힌 줄로만
존재하고, 처리하면 다음 장이 열린다.

### 빈 상태 (계약이 지정한 문구 그대로)

```
┌──────────────────────────────────────────────────────────┐
│  지금 확인할 것은 없어요                                   │
│  지난 확인 이후 기억은 추가됐지만 현재 믿음과 행동 규칙은     │
│  안전하게 유지되고 있어요.                                 │
│                                                          │
│  ─────────────────────────────────────────────────────   │
│  최근 바뀐 믿음  …                                        │
└──────────────────────────────────────────────────────────┘
```

빈 화면을 숨기지 않는다. **완료가 이 제품이 주는 보상이다.**

### 오류 / 근거 부족

```
│  이 항목은 근거를 읽지 못했어요                            │
│  파일이 옮겨졌거나 지워졌을 수 있어요.                      │
│  [ 원본 위치 보기 ]  [ 나중에 ]                            │
```

결론을 꾸며내지 않고 `근거 부족`으로 표시한다.

## §4. 구현 범위 — 세로 조각 하나

**이번에 만드는 루프: "근거가 흔들린 것"만.** 낡은 추론 9건 + 근거가 정정된 state 4건.

| 하는 것 | 안 하는 것 |
|---|---|
| 1단계 카드와 세 버튼 | 2단계 "최근 바뀐 믿음" (다음 조각) |
| 세션 진행률 (n / 총) | 3단계 재배치 (다음 조각) |
| 빈 상태 | 다른 화면 일체 |
| 승인·보류의 서버 반영 | 시각 완성도 |

**수정은 해당 노트 맥락에서** 한다. 별도 관리 화면을 만들지 않고 기존 노트 화면으로 보낸다.

기존 사이드바·탭·헤더·라우팅은 건드리지 않는다. 홈 라우트(`/`)의 내용만 바꾼다.

## §5. 검증할 실제 상태

계약이 지정한 일곱 중 이 조각에 해당하는 것.

1. 확인 항목이 여럿일 때 5초 안에 시작 행동을 찾는가
2. 0개일 때 완료와 안심이 명확한가 — **오늘 볼트로는 인위적으로 비워서 확인해야 한다**
3. 원본 노트가 늘어도 믿음이 안 바뀌었으면 홈이 피드로 넘치지 않는가
4. ~~새 rule이 최상단에 오는가~~ — **오늘 대기 rule이 0건이라 실제 검증 불가.** 가짜 데이터로
   확인하고, 실물 검증은 미결로 남긴다
5. 긴 한국어 제목과 작은 창에서 라벨이 세로로 쪼개지지 않는가
6. 키보드·포커스·다크/라이트 유지

**실제 Electron 창을 캡처해서 본다.** 테스트 통과만으로 완료 선언하지 않는다.
