# 기억 감사와 정비 (memory audit + repair session)

> [[memex UI — 화면별 역할과 사용자 경험]]이 "UI는 감사하고 바로잡는 곳"이라고 정했다.
> 이 문서는 그 정의를 실행 가능한 두 기능으로 옮긴다: 상태를 한 눈에 보는 `stats audit`,
> 그리고 그 상태를 실제로 줄이는 정비 세션.

## 진단 — 기능이 아니라 흐름이 막혀 있다

2026-08-22 실측:

```
노트 1,364          past 1,111 · state 242 · rule 11
저자                 person 1,229 · agent 135 (agent는 전부 state)
출처                 index 757 · claude-code 604 · manual 3
파일 위치            메인 볼트 1,099 · evan-blog 256 · memex 리포 9
링크                 위키 1,182 · 정정 73
note_evidence        0행
```

`Evidence.tsx`는 이미 근거 후보 제안, 선언, "아직 맞아"까지 전부 구현돼 있다. 그런데 선언된
근거가 0행이다. 기능이 없어서가 아니라 **한 번에 한 노트씩 처리하는 입구뿐이라, 107개를
아무도 끝까지 넘기지 않은 것이다.**

홈의 "손볼 것"도 같은 문제를 반대편에서 보여준다. 여섯 줄의 합이 730건이다.
[[memex UI — 화면별 역할과 사용자 경험]]은 "손볼 것 0~3개"로 설계했지만 실제로는 두 번째
통계판이 됐다. **줄어들지 않는 카운터는 할 일이 아니라 부채로 읽힌다.**

그래서 신규 기능보다 먼저 필요한 것은 두 가지다.

1. 지금 상태를 **한 숫자로** 말하는 것 (`stats audit`)
2. 그 숫자를 **한 자리에서 연속으로** 줄이는 것 (정비 세션)

## 원칙

1. **점수는 추측하지 않는다.** 모든 감점은 이미 결정론적으로 세고 있는 값에서 나온다. LLM 0회.
2. **카운터가 아니라 입구다.** 홈의 숫자는 클릭하면 그 일을 실제로 하는 자리로 들어가야 한다.
3. **큐를 만들지 않는다.** 상시 대기열 화면은 여전히 만들지 않는다. 정비는 사람이 열 때만
   존재하는 세션이고, 끝이 있다.
4. **한 세션은 끝난다.** 730건을 보여주지 않고 한 묶음을 보여준다. 끝나면 닫힌다.

## 1. `memex stats audit` — 기억 건강 점수

### 왜 `stats` 하위인가

표면 정책이 "새 top-level보다 기존 명령의 하위 명령을 선호한다"고 정해 뒀고, 감사는
Maintenance(측정) 그룹에 정확히 들어간다. `stats eval`, `stats flashback`과 같은 자리다.

### 점수 설계

네 축, 합 100점. 각 축은 비율이고 감점은 비율의 부족분이다.

| 축 | 배점 | 비율 정의 | 왜 이 배점인가 |
|---|---|---|---|
| 근거 (grounded) | 30 | 근거를 선언한 person state / 전체 person state | 출처 없는 판단은 검증도 무효화도 불가능하다 |
| 신선도 (fresh) | 30 | 낡음 신호가 없는 state / 전체 state | 틀린 기억은 없는 기억보다 나쁘다 |
| 연결 (connected) | 25 | 해결되는 위키 링크 / 전체 위키 링크 | 끊어진 링크는 근거 사슬이 끊긴 것이다 |
| 정돈 (tidy) | 15 | 정리 대상이 아닌 태그 / 전체 태그 | 위생 문제다. 신뢰를 직접 깨지는 않는다 |

분모가 0이면 그 축은 만점으로 본다. 없는 것을 감점하지 않는다.

### 출력

```
기억 건강 점수  62 / 100

근거    0/107 판단이 출처를 말한다              -30
신선도  182/242 판단이 아직 신선하다            -7
연결    1053/1182 링크가 도착한다               -3
정돈    358/780 태그가 정리돼 있다              -8

가장 약한 곳: 근거
  #1841 Opula 백로그 (근거 후보 9개 대기)
  memex stats audit 를 다시 실행하기 전에 정비 세션을 한 번 돌려라
```

`--json`으로 같은 값을 그대로 내보낸다. UI 카드와 공유 이미지가 같은 계산을 재구현하지
않게 하기 위해서다.

### 구현

- `apps/cli/src/services/audit.ts` — 순수 조립. `buildChores`와 `getCorpusStats`가 이미
  세는 값만 쓴다. 새 쿼리는 person state 총계 하나뿐이다.
- `apps/cli/src/commands/audit.ts` — 출력만 담당. `registerStats` 안에서 등록한다.
- 테스트는 점수 계산 자체를 검증한다. 빈 볼트가 100점인지, 분모 0이 만점인지, 축별 감점이
  배점을 넘지 않는지.

## 2. 정비 세션 — 카드 스택

### 무엇을 고치나

첫 판은 **근거 선언 하나만** 다룬다. 이유는 세 가지다.

- 다른 모든 결정론적 판정(정정 전파, 해시 비교)이 여기에 걸려 있다.
- 카드 UI(`Evidence.tsx`의 `Offer`)가 이미 존재한다. 새로 그릴 것이 없다.
- 후보가 이미 계산돼 있다. person state 107개 중 83개가 위키 링크를 갖고 있다.

### 동작

- 홈의 "무엇에서 나왔는지 말하지 않는 판단"을 클릭하면 `/repair/evidence`로 들어간다.
- 한 번에 한 장. 카드 = 노트 하나 + 그 노트의 근거 후보 목록.
- 키보드로만 넘어간다.

| 키 | 동작 |
|---|---|
| `1`~`9` | 후보 켜고 끄기 |
| `Enter` | 선택한 것을 근거로 선언하고 다음 장 |
| `S` | 건너뛰기 (다음 세션에 다시 나온다) |
| `N` | 근거 없음으로 확정 (`still-true`, 추측 판정에 계속 맡긴다) |
| `Esc` | 세션 종료 |

- 기본값은 **모든 후보가 켜진 상태**다. 위키 링크를 이미 손으로 건 것이라 대부분 근거가
  맞고, 사람은 아닌 것만 끄면 된다.
- 한 묶음은 20장이다. 다 넘기면 "20장 정리했다. 87개 남음. 한 판 더 / 그만" 두 버튼만 남는다.

### 왜 자동 승격이 아닌가

state-as-projection 설계가 "위키 링크를 근거로 자동 승격하지 않는다"고 정했다. 참고와 근거는
다르다. 이 세션은 그 결정을 뒤집지 않는다. **제안을 사람 앞에 20개씩 줄 세우는 속도만
바꾼다.** 판단은 여전히 사람이 한 장씩 한다.

### 구현

- `GET /api/repair/evidence?limit=20` — 근거 미선언 person state를 후보 수 내림차순으로
  준다. 홈의 `chores.undeclared`가 상위 5개만 주는 것과 달리 묶음 단위로 준다.
- `apps/ui/src/Repair.tsx` — 카드 스택. 선언은 기존 `PATCH /api/note/:id`의
  `derivesFrom`을, 근거 없음은 기존 `POST /api/still-true/:id`를 그대로 쓴다.
  **새 쓰기 경로를 만들지 않는다.**
- 라우트 `/repair/evidence` 하나. 사이드바에 넣지 않는다. 홈에서만 들어간다. (원칙 3)

## 하지 않는 것

- **top-level `memex audit`** — 표면 정책을 어긴다. 하위 명령으로 충분하다.
- **점수 히스토리 저장** — 지금은 현재 상태만 말한다. 추세는 값이 움직이는 걸 본 다음에.
- **정비 큐 화면** — 세션은 홈에서 들어가고 끝나면 닫힌다. 사이드바에 상주하지 않는다.
- **LLM 근거 분류** — 위키 링크 후보를 켜둔 기본값으로 충분한지 먼저 잰다. 기각률이 높으면
  그때 LLM을 넣는다.
