# [작업지시서] 정정을 제안한다: 값을 묻지 말고 찾아준다 (2026-09-06)

> 운영 계약 #2280 §3 승인 요청서. 코드는 아직 손대지 않았다.
> `2288`의 2차 범위 중 **정정 입력 모드**를 설계한다. §2-1(재추출 금지), §3(게이트 ①),
> §7-1(세션 7)은 그대로 살린다.
>
> 전제는 하나다. **사람이 값을 안다는 가정이 틀렸다.**
> 덱에 올라온 주장의 나이 중앙값은 52일이다. 그 값이 지금 무엇인지는 사람도 모른다.

## 배경

### 1차가 만든 것과 남긴 것

2026-09-06에 `2288` 1차가 들어갔다. 판정 단위가 주장이 됐고, 확인·보류·되돌리기가 붙었다.
남은 것이 정정이고, 그게 이 제품의 존재 이유다.

`2288` §2가 정정을 이렇게 정의했다.

> **바뀌었어요** + 새 값 — 기존 `valid_until=오늘`, `status='closed'`, 새 주장 생성 후 `superseded_by` 연결

`+ 새 값`이 문제다. **그 값을 사람이 갖고 있다는 가정이 이 문장에 숨어 있다.**

### 실측: 사람이 값을 알기 어렵다

2026-09-06 `~/.memex/memex.db`. 덱 대상 미확인 주장 60건 기준.

| | 실측 |
|---|---:|
| 나이 중앙값 | **52일** |
| 최소 · 최대 | 19일 · 102일 |
| 근거 노트에 정정/후속 노트(`amends`·`corrects`)가 달린 것 | **0** |
| 폐기 문장(`invalidates`)이 있는 것 | **0** |
| 같은 태그의 더 나중 노트가 있는 것 | **60 / 60** |

읽는 법은 이렇다.

**답은 볼트 안에 있을 가능성이 높은데, 아무것도 그걸 가리키지 않는다.**
구조화된 정정 사슬은 하나도 없다. 대신 "이 주제로 나중에 쓴 노트가 있다"가 60건 전부에 있다.

두 달 전 자기가 쓰지도 않은 문장을 보고 "지금은 이겁니다"를 빈칸에서 타이핑하는 것은
이 제품이 비개발자에게 시키기로 한 일이 아니다.

### 그래서 이것은 생성 문제가 아니라 검색 문제다

memex가 할 일은 값을 짓는 것이 아니라 **이미 있는 값을 찾아 붙이는 것**이다.
찾지 못하면 짓지 않는다. 그 경계가 이 문서의 전부다.

## 작업 항목

### 1. 제안은 인용할 수 있을 때만 한다

제안을 두 종류로 가른다. 화면도 행동도 다르다.

| | 조건 | memex가 하는 일 | 사람이 하는 일 |
|---|---|---|---|
| **A. 인용 가능** | 나중 노트/주장에 그 값을 말하는 문장이 실제로 있다 | 문장과 출처를 그대로 보여준다 | 연결을 **승인**한다 |
| **B. 인용 불가** | 그런 문장이 없다 | 범위만 좁혀준다. 문장을 만들지 않는다 | 값을 **제공**한다 |

**출처가 없으면 제안하지 않는다.** 이것이 규칙이다.

근거는 `2288` §1-2가 인용한 것과 같다. OpenAI가 사용자 관리형 기억을 폐기한 이유는
목록이 낡고 서로 모순돼서였다. memex가 사람을 남기는 이유는 사람만 가진 정보가 있기 때문인데,
memex가 값을 지어내고 사람이 한 키로 수락하면 **그 정보는 볼트에 들어오지 않는다.**
들어오는 것은 그럴듯한 문장이고, 사람은 근거 있는 문장과 그럴듯한 문장을 구분하지 못한다.

`2288` §6이 확인에 대해 만든 장치(`confirm_depth`)와 같은 문제이고, 정정 쪽이 더 위험하다.
잘못 확인한 주장은 30일 뒤에 다시 물어보지만, **잘못 정정한 주장은 새 사실이 되어 남는다.**

### 2. 후보는 주장에서 뽑는다

후보 출처로 셋을 검토했다.

| 출처 | 장점 | 문제 |
|---|---|---|
| **나중 주장** (`note_claims` 269개) | 입자가 같다. 수락하면 `superseded_by`가 바로 채워진다 | 커버리지 20% |
| 나중 노트 본문 | 넓다 | 인용 단위가 문단이라 "새 값"이 안 된다 |
| `register_events` | 유효기간 스키마가 이미 있다 | 4행뿐. 지금은 재료가 아니다 |

**나중 주장을 1순위로 한다.** 커버리지가 낮은 것은 게이트 ①이 이미 흡수한다 —
쓰이지 않는 주장의 후보 품질은 사용자에게 닿지 않는다.

후보 조건:

- 대상 주장보다 `valid_from`이 나중이다
- `status`가 `closed`·`retracted`가 아니다
- 의미가 가깝다 (임계값은 §6에서 실데이터로 정한다)
- 같은 노트에서 나온 주장은 제외한다 (자기 자신의 이웃 문장은 대체값이 아니다)

후보가 없으면 **나중 노트 목록으로 떨어진다.** 이때 문장은 인용하지 않고 노트만 연다.

### 3. 이미 있는 기계를 겨눈다

새로 만들 것이 적다.

| 있는 것 | 지금 하는 일 | 겨눌 곳 |
|---|---|---|
| `detectStaleState` | 한 노트 근처에 나중 노트가 쌓였는지 찾는다 (36건) | **주장 단위 후보 검색** |
| `draftStateUpdate` | 나중 근거로 state 노트 갱신안을 초안 잡는다 | 인용 불가일 때의 마지막 수단 |
| `note_claims.superseded_by` | 비어 있다 | 수락 시 채운다 |
| `searchNotes` 임베딩 | 노트/청크 벡터 | 주장 텍스트를 질의로 |

`stale_state` 36건은 1차에서 큐에서 뺀 신호다. 무엇이 어떻게 틀렸는지 말하지 못해서였다.
**후보 검색으로 겨누면 그 약점이 사라진다.** 판정을 요구하지 않고 후보만 대기 때문이다.

### 4. 네 번째 행동: 모르겠어요

`2288` §2의 네 판정에 빠진 자리가 있다.

| 상황 | 지금 받을 수 있나 |
|---|---|
| 지금도 맞다 | 예 — 아직 맞아요 |
| 바뀌었고 새 값을 안다 | 예 — 바뀌었어요 |
| 애초에 추출이 틀렸다 | 예 — 원래 틀렸어요 |
| **더 이상 참이 아닌데 뭐가 대신인지 모른다** | **아니오** |

네 번째가 이 문서가 다루는 상황의 정직한 결말이다. 후보도 없고 사람도 모르면
값을 강요하는 설계에서는 **그 카드가 영원히 안 치워진다.**

**스키마는 이미 지원한다.** `valid_until`을 찍고 `superseded_by`를 `NULL`로 둔다.
`status='closed'`의 정확한 의미가 그것이다.

그리고 이건 정보가 없는 것이 아니다. **"지금은 참이 아니다"만으로 회수에서 뺄 수 있다.**
`2288` §8의 상태별 회수 표가 `closed`를 이미 그렇게 정의하고 있다.

### 5. 화면: 정정은 덱에서 이탈한다

`2288` §5가 정한 비대칭을 지킨다. 확인은 리듬, 정정은 이탈이다.
`→` 확인은 카드를 넘기고, `←` 정정은 **덱을 멈추고 입력 모드로 전환**한다.

#### 5-1. 인용 가능한 경우

```
┌────────────────────────────────────────────────────┐
│  AI가 이렇게 말해요                                  │
│                                                    │
│  Opula의 채팅은 Groq에서                            │
│  gpt-oss-120b를 돌린다                              │
│  2026-08-03부터 · 34일째 확인 안 됨                  │
│                                                    │
│  ──────────────────────────────────────────────    │
│  볼트에서 이렇게 찾았어요                            │
│                                                    │
│   ○  Opula의 LLM은 Vercel AI Gateway를 쓴다         │
│      「Opula 공급자 교체」 · 8월 16일                 │
│                                                    │
│   ○  직접 입력할게요                                 │
│      ┌────────────────────────────────────────┐    │
│      │                                        │    │
│      └────────────────────────────────────────┘    │
│                                                    │
│   ○  더 이상 안 맞는데 뭐가 맞는지는 모르겠어요        │
│                                                    │
│  [ 이걸로 바꿀게요 ]        [ 취소 ]                 │
└────────────────────────────────────────────────────┘
```

- 후보는 **최대 3개.** 넷째부터는 고르는 일이 판단보다 비싸진다
- 각 후보는 **문장 + 출처 노트 + 날짜**를 같이 낸다. 셋 중 하나라도 없으면 후보가 아니다
- 직접 입력은 항상 있다. 제안은 지름길이지 관문이 아니다

#### 5-2. 인용 불가능한 경우

```
│  볼트에서 답을 찾지 못했어요                          │
│  이 주장 이후로 같은 주제 노트가 3개 있어요            │
│    「opula 세션 인계 8/16」 · 「가격 재설계」 · …       │
│                                                    │
│   ○  직접 입력할게요   [                        ]   │
│   ○  더 이상 안 맞는데 뭐가 맞는지는 모르겠어요        │
```

**문장을 짓지 않는다.** 노트 제목만 낸다.

#### 5-3. 수락하면 일어나는 일

| 고른 것 | 쓰기 |
|---|---|
| 후보 주장 | 기존 `valid_until=오늘`·`status='closed'`·`superseded_by=후보 id`. 후보는 `confirmed` |
| 직접 입력 | 기존 닫고, 새 주장을 `note_id=NULL`·`author='person'`으로 만들어 연결 |
| 모르겠어요 | 기존 `valid_until=오늘`·`status='closed'`·`superseded_by=NULL` |

직접 입력한 주장은 근거 노트가 없다. **그것이 사실이므로 그대로 기록한다.**
`note_claims.note_id`를 nullable로 바꾸고, 카드에 "사람이 직접 적음"으로 표시한다.

### 6. 임계값은 실데이터로 정한다

유사도 임계값을 미리 정하지 않는다. 콜드 스타트에서 재고 정한다.

- 임계값이 낮으면 관련 없는 후보가 뜨고, 사람은 제안을 안 믿게 된다
- 높으면 후보가 늘 비어서 §5-2로만 떨어진다

측정 방법: 60건 각각에 대해 상위 3후보를 뽑아 **사람이 "이 중에 답이 있다"고 한 비율**을 센다.
`2288` §6과 같은 방식으로, 속도를 막지 않고 값만 다르게 매긴다.

### 이 작업이 건드리지 않는 것

- 앱 셸. 사이드바·탭·헤더·라우팅 그대로. 입력 모드는 `Review.tsx` 안의 상태다
- 게이트 ①. 정정 후보 검색은 이미 덱에 오른 카드에만 돈다
- 재추출 금지(`2288` §2-1). 후보 검색은 읽기만 한다
- 세션 7 (`2288` §7-1). 정정으로 이탈해도 세션 카운트는 유지된다

## 반증 조건

### 이 작업을 폐기해야 하는 신호

| 관측 | 뜻하는 것 |
|---|---|
| 후보 수락률이 **20% 미만** | 볼트가 답을 갖고 있지 않다. 제안은 헛일이고 직접 입력만 남긴다 |
| `모르겠어요`가 **절반 이상** | 이 주장들은 정정 대상이 아니라 폐기 대상이다. 큐 구성을 다시 본다 |
| 직접 입력한 주장이 **한 달 안에 또 정정됨** | 사람의 입력도 낡는다. 근거 없는 주장에 짧은 신선도를 줘야 한다 |
| 후보 3개를 고르는 데 **카드당 30초 초과** | 판단보다 고르기가 비싸다. 후보를 1개로 줄인다 |

### 착수 전에 필요한 실측

**1차 콜드 스타트가 이 문서의 전제를 검증한다.** 지금 덱에 `←`(정정 필요)가 붙어 있고,
그 수가 `claim_actions`의 `correct-wanted`로 쌓인다.

| 관측 | 이 문서에 대한 뜻 |
|---|---|
| `correct-wanted`가 **0건** | 정정 자체가 필요 없다. 이 문서를 폐기한다 |
| 1~5건 | 제안까지 만들 값이 없다. 직접 입력만 붙인다 |
| **6건 이상** | 이 문서대로 만든다 |

### 이미 알고 있는 약점

| 약점 | 실측 | 완화 |
|---|---|---|
| 주장 커버리지 20% | 255개 state 중 52개만 추출 | 게이트 ①이 흡수 |
| 구조화된 정정 사슬 0건 | `amends`·`invalidates` 모두 0 | 의미 유사도로 대체. 그래서 §6이 필요 |
| 후보도 LLM이 뽑은 주장 | 검증이 재귀함 | 후보는 **출처와 함께만** 제시. 사람이 원문을 볼 수 있다 |
| 사람이 직접 적은 주장에 근거가 없다 | `note_id` NULL | 그대로 표시. 신선도를 짧게 줄지는 반증 조건 3번으로 정한다 |

## 완료 게이트

### 1차 범위

후보 검색 + 인용 가능/불가 두 화면 + 세 가지 수락 경로(후보·직접·모르겠어요).
`superseded_by` 체인 조회 UI는 다음으로 미룬다.

### 착수 전 승인이 필요한 것

1. **출처 없으면 제안하지 않는 것.** 인용 불가일 때 LLM으로 문장을 짓지 않는다
2. **후보를 나중 주장에서 뽑는 것.** 노트 본문이 아니라
3. **후보 최대 3개**
4. **`모르겠어요`를 네 번째 행동으로 추가하는 것.** `closed` + `superseded_by=NULL`
5. **`note_claims.note_id`를 nullable로 바꾸는 것.** 사람이 직접 적은 주장을 담기 위해
6. **유사도 임계값을 콜드 스타트 실측으로 정하는 것**

### 완료 판정

- [ ] 후보가 있는 카드에서 문장·출처 노트·날짜 셋이 모두 뜬다
- [ ] 후보가 없으면 문장을 짓지 않고 노트 제목만 낸다
- [ ] 후보를 수락하면 `superseded_by`가 채워지고 기존 주장이 `closed`가 된다
- [ ] 직접 입력한 주장이 `note_id=NULL`·`author='person'`으로 저장된다
- [ ] `모르겠어요`가 `closed` + `superseded_by=NULL`로 닫는다
- [ ] `⌘Z`로 정정 전체가 되돌아간다 (닫힌 주장이 열리고 새 주장이 사라진다)
- [ ] 정정 중에 덱이 멈춰 있고, 취소하면 같은 카드로 돌아온다
- [ ] 사이드바·탭·헤더·라우팅 파일에 변경이 없다

마지막 항목이 실패하면 나머지가 통과해도 이 작업은 계약 위반이다.
