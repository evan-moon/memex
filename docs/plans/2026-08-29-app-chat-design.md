# 앱 안에서 대화로 기억을 고친다 — Electron 셸과 provider 레이어

> `2026-08-28-what-memex-is.md`가 **누가 쓰는가**를 정했고, 그 문서가 남긴 열린 질문 중
> 마지막 하나가 **"비개발자에게 배포를 어떻게 하는가"**다. 이 문서는 그 답과, 앱이 생기면
> 비로소 가능해지는 것 하나(대화로 고치기)를 같이 설계한다.
>
> **초안을 GPT-5(Codex)에 적대적 검토를 붙여 두 곳을 뒤집었다.** 3절(대화창=MCP 클라이언트)과
> 4절(즉시 쓰고 되말하기)이 초안에서 틀렸다. 10절에 무엇이 뒤집혔는지 남긴다.

## 0. 무엇을 만드나

memex 앱 안에 대화창을 둔다. 사람이 "opula 트라이얼 30일로 바뀌었어"라고 쓰면 값이 고쳐지고,
"그 회고 노트에서 X는 틀렸어"라고 쓰면 정정 노트가 생긴다.

**왜 앱 안이어야 하나.** 컨셉 3번은 사람이 memex를 쓰는 유일한 이유가 "AI가 틀리게 기억한
것을 고치는 것"이라고 정했다. 지금 그 교정은 **폼**이다 — 값을 지우고 다시 타이핑한다.
그런데 사람이 틀렸다는 걸 아는 순간의 자연스러운 형태는 폼이 아니라 **문장**이다.

## 1. 제약 — 순서대로 무겁다

### 1-1. 구독 OAuth 토큰은 쓸 수 없다 (memex #2081, 2026-08-29 재확인)

Anthropic이 2026-02-19 문서를 갱신해 명시했다: Free·Pro·Max의 OAuth 토큰은 **Claude Code와
Claude.ai 전용**이고, **Agent SDK를 포함한** 다른 제품·툴·서비스에 쓰는 것은 소비자 약관
위반이다. 차단은 2026년 1월부터다. Anthropic 측 권고는 "사업을 만든다면 API 키를 쓰라"다.
**#2081은 유효하고 노트보다 범위가 넓다 — SDK도 막힌다.**

**경계를 정확히 그어야 한다.** 막힌 것은 *토큰을 꺼내 다른 곳에서 쓰는 것*이다. `claude` CLI를
실행하는 것은 인가된 표면이 자기 인증으로 도는 것이라 다르다. **그러나 서드파티 제품이 최종
사용자의 구독을 대신 소모하도록 오케스트레이션하는 것은 회색지대다.** 개인 도구로 쓰는 동안은
문제가 없지만 배포 시점에는 이것이 제품의 제약이 된다.

> **이것은 열린 질문이 아니라 launch gate였다** (9절). 조사 결과 대부분 닫혔다 — memex가
> 자격증명을 아예 만지지 않는 경로가 있고, `--console`이면 종량 과금이라 질문 자체가 거의
> 사라진다. 남은 것은 배포 전 Anthropic 확인 하나다.

### 1-2. 대상은 비개발자다 (컨셉 4번)

그런데 memex의 LLM 기능은 지금 **전부** 로컬 `claude` 셸아웃이다 — `draft.ts:146`
`inference-draft.ts:57` `conflicts.ts:73` `claim-extract.ts:60`. `draft-no-claude` 에러
코드까지 있다. **이 모순은 이번에 생기는 것이 아니라 이미 있는 것이고, 이 문서가 그걸
드러낸다.**

`연결` 화면은 Claude Desktop·Claude Code·Codex·Cursor를 감지하지만(`mcp-clients/clients.ts:23`)
지금은 **감지만 하고 설치·로그인은 안내하지 않는다.** 9절이 그 경로가 실재함을 보인다 —
이 모순은 원리적 제약이 아니라 아직 안 만든 화면이다.

### 1-3. 비용 모델이 없다

`draft.ts:163`은 `total_cost_usd`를 **의도적으로 버린다** — 구독으로 도는 것을 전제하고, 그
숫자가 오해를 준다고 판단했기 때문이다. 주석에 그렇게 적혀 있다. 이건 "비용 모델을 안 만든
것"이 아니라 **구독을 전제해서 비용이라는 개념 자체가 없는 것**이다. provider가 BYOK가 되는
순간 예산·프리플라이트가 통째로 없다.

## 2. Aside에서 가져오는 것

Aside(`at.studio.AsideBrowser`, At Inc.)는 서드파티인데도 1-1에 걸리지 않는다. CLI 표면이
답을 말한다:

```
-m, --model <model>        provider/model
-p, --provider <provider>
   account                 Inspect and select Aside CLI accounts
예: openai/gpt-5.4 · openai-codex/gpt-5.5 · anthropic + claude-opus-4-6
```

**`openai-codex`가 provider로 따로 있다.** 토큰을 쥐는 대신 **벤더의 1st-party CLI에게
시키고**, provider와 account를 갈아끼울 수 있는 축으로 만들었다.

### 결정 — provider 레이어를 판다

```
packages/llm/
  claude-code.ts    `claude` 셸아웃 (기존 네 곳이 하던 것)
  codex.ts          `codex` 셸아웃
  anthropic.ts      BYOK, sk-ant-api03-
```

호출부는 커맨드 문자열을 조립하지 않고 타입 있는 옵션 객체를 넘긴다. **기존 네 곳을 먼저 이
레이어로 옮긴다.** 대화창은 다섯 번째 호출부이고, 다섯이 되기 전에 경계를 만들어야 한다.

이 리팩터는 1-1의 결론과 **무관하게 이득이다.** 그래서 순서상 맨 앞이다.

## 3. 대화창은 MCP 클라이언트가 "아니다"

> **초안이 여기서 틀렸다.** "memex는 이미 MCP 서버가 있으니 대화창은 그걸 붙이면 끝"이라고
> 썼는데, 검토가 두 가지를 짚었고 둘 다 리포에서 확인됐다.

**첫째, MCP 클라이언트는 `claude` CLI이지 앱이 아니다.** MCP는 모델과 서버 사이의 툴 호출을
푼다. 앱이 져야 하는 것 — 턴 상태, 취소, 진행 표시, 에러 표면, 권한 경계, 결과 렌더링 — 은
아무것도 풀어주지 않는다.

**둘째, MCP 표면을 그대로 쓰면 엉뚱한 에이전트 정책이 딸려온다.** `apps/mcp/src/index.ts:69`의
지침은 이렇게 시작한다:

> *"At the end of any conversation that contains valuable context, call save_note **without
> asking the user**."*

이 앱에 사람이 오는 이유는 **고치러 오는 것**이지 새 기억을 만들러 오는 것이 아니다
(컨셉 1번). 그 지침을 그대로 물려받으면 대화창은 **교정 도구가 아니라 또 하나의 기록기**가
된다.

**셋째, 툴 응답은 개발자용 산문이다.** `save-note.ts:104`는 `distance: 0.420` 같은 값을
그대로 뱉고, `set-register.ts:84`는 predicate 키 분기를 경고한다. 이걸 비개발자에게 그대로
보여줄 수 없고, "Opula 트라이얼을 14일 → 30일로 바꿨어요 · 되돌리기"로 번역하는 층은
**이름만 다른 새 API다.**

### 결정 — 도메인 연산은 재사용하고, 표면은 새로 판다

```
apps/desktop/chat/
  turn.ts        한 번의 교정 = 의도 해석 → 계획 → (확인) → 실행 → 되말하기
  render.ts      툴 결과 → 사람의 문장
  errors.ts      아래 표의 여덟 가지를 각각 다른 문장으로
```

호출은 `@memex/core`·`@memex/db`의 **함수를 직접** 부른다(앱은 이미 인프로세스다). MCP는
*다른 세션의 Claude*를 위한 표면으로 남는다. 재사용하는 것은 **쓰기 의미론**이지 툴 표면이
아니다.

**에러 표면** — 지금 코드는 `ENOENT → no-claude` 하나만 정규화한다(`draft.ts:184`). 대화창은
최소 이만큼을 구분해야 한다: CLI 없음 · CLI 로그아웃 · 구독 거부 · 모델 거부 · 잘못된 툴
인자 · 중단됨 · 부분 쓰기 · 오프라인.

**대화 상태** — `claude`는 턴마다 새 프로세스다(`execFile`). 다만 `--resume`/`--continue`와
`--output-format stream-json`이 있어서 세션을 이어붙일 수는 있다. 히스토리를 영속화하지 않는
결정(9절)과 별개로 **교정 한 건이 끝날 때까지의 단기 상태는 앱이 들고 있어야 한다.**

## 4. 안전장치 — 즉시 쓰기는 좁은 경우에만

> **초안이 여기서도 틀렸다.** "전부 즉시 쓰고 되말한다"고 썼는데, 교정 도구에서 그건
> **두 번째 오해를 되돌리기 어렵게 만든다.**

### 왜 되말하기만으로 부족한가 — 구체적 실패 셋

1. **predicate가 갈린다.** "트라이얼 30일"이 `trial.duration`인지 `trial_length`인지는 모델이
   고른다. `register.ts:101`은 **의도적으로** 유사 키를 합치지 않고 각자 `provisional` id를
   준다. 되말하기는 **이미 fork가 생긴 뒤에** 그 사실을 알린다.
2. **`amends`가 빗나간다.** `save-note.ts:95`는 `amends`가 없는 id면 저장 후에 경고한다. 사용자
   손에는 *잘못된 새 기억 + 그 교정을 다시 교정하는 일*이 남는다.
3. **register 되돌리기는 되돌리기가 아니다.** `register.ts:157`은 append-only다. 이전 값을 다시
   쓰면 tip은 돌아오지만 **잘못된 이벤트는 회수되지 않고, 되돌린 행위가 사람 이름으로 하나 더
   기록된다.** 감사 기록으로는 옳지만 UI가 그렇게 말해야 한다.

### 결정 — 두 단으로 가른다

| | 언제 | 어떻게 |
|---|---|---|
| **즉시 쓰기** | 대상이 **이미 화면에 있고**, 필드 하나, 기존 키, 모호함 없음 | 쓰고 한 줄로 되말한다 |
| **미리보기 후 확인** | 모델이 노트를 **고르거나**, 새 predicate를 만들거나, 둘 이상을 바꾸거나, 서술형 노트를 만들 때 | 무엇을 바꿀지 보여주고 누르면 실행 |
| `layer=rule` | 항상 | 기존대로 `provisional` |
| `delete_note` | — | 대화창에 노출하지 않는다 |
| `past` 정정 | 항상 | 새 노트 + `amends`. 원문을 고치지 않는다 |

즉시 쓰기의 조건에 **"대상이 이미 화면에 있고"**가 들어가는 게 핵심이다. `지금 참인 것`
화면에서 값을 보며 "이거 30일이야"라고 하는 것은 모호하지 않다. 빈 대화창에 같은 문장을
치는 것은 모호하다. **같은 문장이라도 맥락이 확인 여부를 정한다.**

## 5. Electron 셸 — 얇은 래퍼가 아니다

`apps/ui`가 Vite 앱인 건 맞지만, 배포 UI는 **`page.ts`로 CLI 빌드에 임베드되어 loopback
HTTP 서버가 서빙한다**(`server.ts:603`, `commands/ui.ts:13`). Electron이 져야 하는 것:

- Node 런타임 번들 (`apps/cli/package.json`이 Node >=22를 요구한다)
- 자식 서버 프로세스의 생명주기·크래시 복구
- 고정 포트(4321) 대신 빈 포트 잡아 렌더러에 넘기기
- renderer/preload 보안 경계
- 패키저 선택 · 하드닝 런타임 · 네이티브 모듈 서명 · 공증 제출·스테이플 · 업데이트 전략

**리포에 Electron 도구는 아직 하나도 없다** — 락파일의 `electron-to-chromium`은 브라우저
데이터 의존성이지 Electron이 아니다.

## 6. 첫 실행 — 릴리스 요구사항이지 열린 질문이 아니다

`packages/embed/src/index.ts:10`이 `Xenova/multilingual-e5-base`(q8, ~450MB)를 받는다.
지금 두 경로가 **서로 다르게** 동작한다:

- `memex ui`는 첫 검색까지 **미룬다**(`commands/ui.ts:23`)
- MCP 서버는 **기동 시 받는다**(`apps/mcp/src/index.ts:34`)

앱은 둘 중 무엇을 약속할지 정하고, **진행률·재시도·오프라인·디스크 부족·캐시 손상**을 화면으로
가져야 한다. 그리고 정해야 할 것 하나: **임베딩이 준비되기 전에 교정이 되는가.** 값 교정
(register)은 임베딩이 필요 없고 검색은 필요하다. 여기서 갈 수 있다.

## 7. 안 만드는 것

- **대화 히스토리의 영속화** — 대화는 교정의 수단이지 기억이 아니다
- **멀티 provider 선택 UI** — provider 레이어는 파되 화면은 나중에
- **앱 안 자동 업데이트** — 배포 경로가 정해진 다음
- **스트리밍 토큰 렌더링** — 교정은 한 문장이고 응답도 한 문장이다

## 8. 착수 순서

1. **`packages/llm` provider 레이어** — 기존 네 곳을 옮긴다. 1-1과 무관하게 이득
2. **온보딩 화면** (9절) — `연결` 화면을 확장한다. 설치됨? → 로그인됨? → memex 등록됨?
   세 상태를 `claude auth status --json`으로 읽고, 각 단계에 버튼과 **실패 시 수동 안내**를 둔다.
   이건 Electron 없이 지금 웹 UI에서 만들 수 있고, 만들면 1-2의 모순이 실제로 닫힌다
3. **대화창** — `지금 참인 것` 화면 **안에서** 시작한다. 빈 대화창이 아니라 값 옆의 한 줄
   입력이면 4절의 "대상이 이미 화면에 있고"가 자동으로 만족된다
4. **Electron 셸** — 5·6절이 설계된 다음
5. 배포·서명·공증

3번을 화면 안에서 시작하는 것이 이 순서의 핵심이다. **가장 좁고 가장 안전한 교정부터 만들면
대화창의 가치를 Electron 없이 검증할 수 있다.**

## 9. Launch gate — 그리고 그 답 (2026-08-29 조사)

초안은 "비개발자가 `claude` CLI를 못 쓴다"를 막힌 문제로 뒀다. **막히지 않았다.** Claude Code가
기계가 쓸 수 있는 설치·인증 표면을 이미 갖고 있다.

| 단계 | 표면 | 앱이 얻는 것 |
|---|---|---|
| 설치 | `curl -fsSL https://claude.ai/install.sh \| bash` | 네이티브 바이너리, **Node 불필요** |
| 갱신 | `claude install [stable\|latest\|<version>]` | 버전 고정 가능 |
| 로그인 | `claude auth login --claudeai` (기본) / `--console` / `--sso` / `--email <email>` | 브라우저에서 Anthropic 자기 페이지 |
| 상태 | `claude auth status --json` | `loggedIn` · `authMethod` · `subscriptionType` |

```json
{ "loggedIn": true, "authMethod": "claude.ai", "subscriptionType": "max" }
```

**TUI 스크래핑이 필요 없다.** `연결` 화면이 이미 하는 일(감지 → 버튼 → 상태)과 같은 모양의
상태 머신이다: 설치됨? → 로그인됨? → memex 등록됨?

### 이것이 1-1을 어떻게 바꾸나

**memex가 자격증명을 아예 만지지 않는다.** 설치는 Anthropic의 스크립트, 로그인은 Anthropic의
페이지, 토큰은 Claude Code 자기 저장소. 앱은 `loggedIn` 불리언만 읽는다. "토큰을 꺼내
쓴다"는 구도가 성립하지 않는다.

**`--console`이 BYOK를 대신한다.** *"Anthropic Console (API usage billing) instead of Claude
subscription"* — 종량 과금 경로가 Claude Code 안에 이미 있고, 그것이 Anthropic이 권고한
상업용 경로다. **memex가 API 키 온보딩과 비밀값 보관을 직접 만들 이유가 없다.** 1-3(비용
모델 부재)도 이 경로에서는 Anthropic Console이 진다.

### 남은 진짜 벽 — CLI가 아니라 계정이다

1. **원클릭이 아니라 3~4클릭이다.** 브라우저 OAuth는 사용자가 직접 로그인해야 한다. 이건
   우회 대상이 아니라 그래야 맞는 부분이다
2. **앱이 구독도 결제수단도 만들어줄 수 없다.** `--claudeai`는 구독이, `--console`은 Anthropic
   계정과 결제수단이 필요하다. **비개발자 온보딩의 벽은 CLI가 아니라 여기다**
3. **`curl | bash`를 서명된 앱이 대신 실행하는 것** — 버전 핀 + 체크섬 + 실행 전 고지로
   완화하되, 원격 코드를 대신 실행한다는 사실은 남는다. MDM 잠긴 머신에서는 실패한다
4. **이 표면은 공개 API 계약이 아니다.** `auth status --json`의 키도 `auth login`의 플래그도
   예고 없이 바뀔 수 있고, 바뀌면 **모든 사용자의 온보딩이 조용히 깨진다.** 감지가 실패하면
   항상 수동 안내로 폴백해야 하고, 이 경로는 `연결` 화면의 `elsewhere` 상태처럼 **틀렸다는
   것을 화면이 말할 수 있어야** 한다

### 결론

`claude-code` 단일 provider는 **더 이상 개발자 알파 제약이 아니다.** 다만 v1의 성공 조건이
"CLI를 깔아준다"에서 **"계정과 결제를 가진 사람을 어떻게 데려오나"**로 옮겨간 것이므로,
그것은 엔지니어링이 아니라 제품 결정이다.

> 1-1의 회색지대는 **줄었지만 사라지지 않았다.** 서드파티 제품이 사용자의 구독 소비를
> 오케스트레이션한다는 점은 그대로다. 비개발자에게 배포하기 전에 Anthropic에 확인하는 것이
> 여전히 가장 싼 검증이다. `--console` 경로만 쓰면 그 질문 자체가 대부분 사라진다.
