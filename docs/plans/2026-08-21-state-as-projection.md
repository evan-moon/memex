# state를 "선언된 투영"으로 — 설계

> past 불변은 유지한다. 바꾸는 것은 `state`가 **무엇에서 나왔는지 말하지 않는다**는 점 하나다.

## 문제

`state`는 이미 CQRS의 read model이다. `past`가 이벤트 로그이고, `state`는 "그래서 지금 어떤가"를 사람이 손으로 유지하는 투영이다. 그런데 그 투영이 **자기 근거를 선언하지 않는다.**

그래서 낡음을 판정할 방법이 추측밖에 없다. 지금 `detectStaleState`가 하는 일:

```
state 노트마다 → 임베딩이 가까운(<0.45) past 노트 중
                 updated_at 이후에 생긴 게 3개 이상이면 → 낡았다고 본다
```

세 가지가 잘못된다.

1. **근거가 아닌 것을 근거로 센다.** 60개 신호 중 28개(47%)가 에이전트 memory 파일을 가리켰다. 지금은 author 축이 생겨 걸러낼 수 있지만, 남은 32개도 "의미가 가까운 노트"일 뿐 이 투영이 실제로 딛고 선 기록인지는 아무도 모른다.
2. **오타를 고쳐도 낡음이 초기화된다.** 판정 기준이 `updated_at`이라, 한 글자만 고쳐도 쌓여 있던 근거가 리셋된다.
3. **왜 낡았는지 말하지 못한다.** "관련 노트 3개가 이후에 생겼다"까지가 전부다. 어떤 판단이 왜 흔들리는지는 사람이 다시 읽어야 안다.

같은 시스템 안에 **이미 제대로 된 투영이 하나 더 있다.** `inferences`는 근거 노트 목록과 각 노트의 mint 시점 content 해시를 들고 있고, `refreshInferenceStaleness()`가 해시 비교로 낡음을 **계산**한다. 추측하지 않는다.

| | state 노트 | inference |
|---|---|---|
| 만드는 주체 | 사람 | LLM |
| 근거 | 선언 안 함 | `inference_evidence`에 노트별 기록 |
| 낡음 판정 | 임베딩 근접도 + 날짜 (추측) | content 해시 비교 (계산) |
| 검색에 나오나 | 나온다 | 나오지 않는다 (model collapse 방지) |

state를 없애 inference로 합치는 안은 택하지 않는다. **"내가 이렇게 결정했다"와 "기계가 이렇게 추론한다"는 다른 물건이고**, 검색 노출 여부가 다른 것도 그 때문이다. 필요한 것은 통합이 아니라, state가 inference처럼 **근거를 말하게 하는 것**이다.

## 낡음은 한 종류가 아니다

이 설계에서 가장 중요한 구분이다. 섞으면 또 추측으로 돌아간다.

**(A) 근거가 정정됐다** — 결정론적. `amends` 그래프만 보면 된다. 선언된 근거 중 하나를 정정하는 노트가 이 투영보다 나중에 쓰였으면, 이 투영은 확실히 낡았고 **어떤 정정 때문인지 이름까지 말할 수 있다.**

**(B) 근거의 내용이 바뀌었다** — 결정론적. 해시 비교. 다만 past가 불변이라 거의 안 일어난다. state·rule을 근거로 삼았거나, Obsidian에서 직접 고쳤을 때만 걸린다.

**(C) 새 근거가 생겼다** — **여전히 추측이다.** 존재하지 않던 노트를 해시로 알 방법은 없다. 이건 계속 휴리스틱이어야 한다.

### 정직한 측정 결과

이 볼트에 (A)를 지금 적용하면 **0건이 나온다.**

```
정정된 노트를 참조하는 person state 노트          9
  그중 정정이 state 노트보다 나중인 것            0
현재 stale_state 신호 (추측)                     60
```

9개 전부 정정이 state 노트보다 **먼저** 쓰였다 — 이미 반영했다는 뜻이다. 그러니 **(A)는 옳지만 지금은 조용하다.** 60개를 대체하지 않는다. 앞으로 쓰는 정정부터 걸린다.

즉 근거 선언의 값어치는 "60개를 없앤다"가 아니라 세 가지다.

1. **출처가 보인다.** "이 판단은 이 기록들에서 나왔다"를 화면에서 열어볼 수 있다 — #1437이 moat로 꼽은 Verifiability가 state 노트까지 온다.
2. **(C)를 좁힐 수 있다.** "의미가 가까운 아무 노트"에서 "이 투영이 딛고 선 기록들과 같은 주제인 노트"로. 얼마나 좁아지는지는 만든 뒤 재야 한다(아래 검증 계획).
3. **앞으로의 정정이 자동으로 전파된다.**

## 설계

### 1. 근거를 어디에 두나

**frontmatter가 정본이다.**

```yaml
---
title: Opula 유료화 전략
layer: state
derives_from: [1234, 1456, 1502]
---
```

파일이 정본이라 Obsidian에서 보이고 재인덱싱을 견딘다 — interop moat를 지키는 유일한 선택. DB는 파생이다.

`note_evidence` 테이블은 `inference_evidence`를 그대로 본뜬다.

```sql
CREATE TABLE note_evidence (
  note_id     INTEGER NOT NULL,
  source_id   INTEGER NOT NULL,
  source_hash TEXT    NOT NULL,   -- 선언 시점 본문 해시
  declared_at INTEGER NOT NULL,
  PRIMARY KEY (note_id, source_id)
);
```

`note_links`를 쓰지 않는 이유: PK가 (source_id, target_id, source)뿐이라 해시를 둘 자리가 없고, 위키 링크는 "참고"와 "근거"를 구분하지 못한다.

### 2. 무엇을 해싱하나

`bodyOf(content)` — 프론트매터를 뺀 본문. 태그를 하나 고쳤다고 투영이 낡지는 않는다.

### 3. 판정

```
derived_stale(note):
  A. 선언된 근거 중 amends 대상이 있고, 그 정정이 note.updated_at 이후 → stale (정정 노트 이름 첨부)
  B. 선언된 근거의 현재 본문 해시 ≠ 선언 시점 해시   → stale (바뀐 근거 이름 첨부)
  C. 근거를 선언한 노트는 여기서 끝. 추측하지 않는다.
```

`detectStaleState`(추측)는 **근거를 선언하지 않은 state 노트에만** 남긴다. 선언이 그 노트의 추측을 끈다. 마이그레이션이 진행될수록 추측이 줄어드는 구조다.

### 4. 화면

이미 있는 것을 그대로 쓴다. `StalePanel`은 지금도 "관련 노트가 쌓였다 → Claude가 초안 → diff + 왜 바꿨는지 → 저장"을 한다. 바뀌는 것은 **초안이 읽는 근거가 추측이 아니라 선언된 것**이라는 점뿐이다.

노트 화면에 근거 섹션을 추가한다 — "이 판단이 딛고 선 기록", 각 항목에 정정됨/바뀜 표시. 편집기에서 근거를 추가·제거할 수 있게 한다.

### 5. 마이그레이션

기존 107개(person state)는 근거가 없다. 위키 링크로 부트스트랩한다.

```
person state 노트                   107
  위키 링크 1개 이상 가진 것          83 (78%)
  3개 이상                            33
  하나도 없는 것                      24
```

링크가 곧 근거는 아니므로(참고 링크가 섞인다) **제안 → 사람이 확인 → 적용**으로 간다. 태그 화면과 같은 방식이다. 24개는 사람이 직접 채우거나 비워 둔다 — 비어 있으면 지금의 추측이 계속 담당한다.

## 검증 계획

만들고 나서 재야 할 것 하나: **(C)를 근거 기반으로 좁히면 신호가 얼마나 정확해지나.**

- 지금: state 노트당 "임베딩 <0.45 + updated_at 이후 past" 3개 이상
- 이후: "선언된 근거와 태그/폴더를 공유하고 가장 최근 근거보다 나중인 past"
- 비교: 신호 수, 그리고 사람이 실제로 "이건 아직 맞아"로 기각하는 비율

기각률이 안 떨어지면 좁히기가 실패한 것이므로 되돌린다. `memex stats flashback`처럼 측정 명령을 하나 두는 편이 낫다.

## 하지 않는 것

- **state 폐지** — 사람이 내린 판단과 기계가 뽑은 가설을 한 층으로 합치지 않는다.
- **매번 LLM으로 투영** — "기억을 모아 현재 상태를 추론"을 요청 시마다 LLM으로 하면 비싸고, #1437이 경고한 model collapse 경로가 다시 열린다. 투영은 사람이 쓰고, 무효화는 계산으로 한다.
- **위키 링크를 근거로 자동 승격** — 참고와 근거는 다르다. 제안까지만 한다.
- **past 수정** — 이 설계가 지키려는 바로 그것이다.

## 단계

1. `note_evidence` 테이블 + frontmatter `derives_from` 왕복(읽기·쓰기·재인덱싱 보존)
2. (A)(B) 판정 + 근거 선언 노트를 `detectStaleState`에서 제외
3. 노트 화면의 근거 섹션 + 편집기에서 근거 편집
4. 위키 링크 부트스트랩 제안 화면
5. (C) 좁히기 + 측정
