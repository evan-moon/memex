# 모순 탐지 — 낡음 다음에 오는 것

> [[기억 감사와 정비 (memory audit + repair session)]]에서 F2로 미뤄둔 것.
> 낡음은 시간의 함수고 모순은 내용의 함수다. 지금까지 memex는 앞의 것만 알았다.

## 왜 별개인가

`stale_state`는 "이 판단 뒤로 관련 기록이 쌓였다"까지만 말한다. 판단 두 개가 **서로** 따를 수
없는 상태는 아무 데서도 안 잡힌다. 실제로 코드 전체에 contradiction이라는 단어가 없었다.

정정(`amends`) 73건이 있지만 그건 사람이 **이미 알아채고 선언한** 것이다. 아직 모르는 충돌을
찾는 장치가 없다.

## 왜 신호가 판정까지 하지 않는가

`signals.ts`의 계약은 "Lv1 deterministic, LLM 0, cannot self-poison"이다. 모순 판정은
LLM 없이는 불가능하므로 신호가 될 수 없다.

그리고 **임베딩만으로는 원리적으로 안 된다.** 임베딩은 주장과 그 부정을 나란히 놓는다.
"A로 간다"와 "A는 버린다"의 거리는 아주 가깝다. 그래서 거리는 *같은 주제인가*만 답할 수 있고
*같은 결론인가*는 답하지 못한다. 지금 "중복 후보" 신호와 모순 후보가 같은 풀에서 나오는 것도
같은 이유다.

그래서 층을 갈랐다.

| | 하는 일 | 어디에 산다 |
|---|---|---|
| `detectConflictPairs` | 후보 지명 (결정론) | `signals.ts` |
| `signals conflicts` | 4지선다 판정 (LLM) | CLI |
| 판정 결과 | 근거 해시를 가진 기계 주장 | `inferences` |

## 지명 규칙

- **`rule`은 전수 비교.** 11개면 55쌍이다. rule은 에이전트 행동을 직접 지배하므로 여기
  모순이 있으면 피해가 제일 크고, 개수가 적어 다 물어봐도 싸다.
- **`state`는 벡터로 좁힌다.** 거리 < 0.35, 같은 레이어끼리만. 이 볼트에서 8쌍이 나왔다.
- **`past`는 지명하지 않는다.** 기록은 무엇이 있었는지 말할 뿐 서로 반박하지 않는다. past가
  불변인 것과 같은 이유다.
- **정정으로 이미 화해한 쌍은 제외한다.** `amends`가 걸려 있다는 건 저자가 어느 쪽이
  살아남는지 이미 답했다는 뜻이다.
- **가까운 쌍부터 묻는다.** rule 전수 비교에도 임베딩 거리를 읽어 정렬만 한다. `--limit`으로
  중간에 끊기는 실행이 관계없는 두 rule에 호출을 쓰지 않도록.

## 판정

4지선다이고, 무해한 세 가지를 **소리 내어 이름 붙이는 것**이 설계의 핵심이다.

```
CONTRADICTION  둘 다 따르는 게 불가능하거나, 한쪽이 다른 쪽을 부정한다
SAME           같은 말이다. 한쪽이 중복이다
COMPLEMENT     둘 다 성립한다. 한쪽이 범위를 좁히거나 확장한다
UNRELATED      다른 주제다
```

무서운 실패는 "모순을 놓치는 것"이 아니라 **"관련 있는 모든 쌍을 모순이라고 부르는 것"**이다.
그러면 신호가 죽는다. 그래서 프롬프트가 톤이나 표현 차이로 판단하지 말고 *각자 무엇을
약속하는가*로 판단하라고 명시한다.

## 왜 결과가 inference인가

"이 둘이 충돌한다"는 **기계가 만든 주장**이다. 그리고 `inferences`는 이미 그것을 위해 설계돼
있다: 근거 노트 + mint 시점 본문 해시 + 모델/프롬프트 + 해시 비교로 계산되는 무효화 +
검색 제외(model collapse 방지) + 폐기/승격 동사 + `/inference/:id` 화면.

**스키마 변경 0으로 전부 얻는다.** 그리고 근거가 두 노트이므로 양쪽 노트 화면의 "이 노트를
근거로 삼은 가설"에 자동으로 뜬다. 큐 화면을 만들지 않고도 맥락 속에서 만나게 된다.

## 질문은 한 번만 한다

판정이 끝나면 후보 신호는 즉시 `minted`(모순) 또는 `dismissed`(나머지)로 닫힌다. `new`로
남기지 않는다. 이유가 두 개다.

1. `retireResolved`가 `new` 신호를 지우므로 살아남지 못한다.
2. 열린 채로 두면 다음 실행이 같은 쌍에 또 돈을 쓴다. `upsertSignal`의 `INSERT OR IGNORE`가
   이미 triage된 상태를 보존하므로, 닫아두면 영원히 다시 안 묻는다.

## 실측 (2026-08-22)

```
후보 63쌍  =  rule 전수 55  +  state 벡터 8
1순위      #1840 ↔ #1841  (Opula 백로그, 한쪽이 다른 쪽의 "완전판")
```

정렬이 실제로 작동한다는 증거다. 이 쌍은 대체 관계로 알려져 있었지만 둘 다 `rule`로 살아
있어서, 에이전트가 #1840을 먼저 집으면 낡은 지침으로 움직인다.

### 첫 5쌍 판정 결과

```
[1/5] #1840 × #1841 … same
[2/5] #1644 × #1944 … same
[3/5] #1612 × #1617 … complement
[4/5] #1607 × #1612 … complement
[5/5] #1758 × #1975 … complement
```

모순 0건. 두 가지를 배웠다.

**하나. 프롬프트가 과잉 판정하지 않는다.** 가장 무서웠던 실패 모드는 피했다. 거리 0.35 안에
있는 다섯 쌍을 전부 모순이라고 부를 수도 있었는데, 세 쌍을 complement로 정확히 갈랐다.

**둘. `same`을 버린 것이 설계 결함이었다.** 이 작업을 시작한 이유가 #1840/#1841이었는데
판정은 `same`이 맞았고 (둘은 모순이 아니라 중복이다, 한쪽이 다른 쪽의 "완전판"이다)
초판 구현은 그걸 무해하다고 보고 조용히 dismiss했다. **찾으러 나선 것을 찾아놓고 버린 셈이다.**

`rule` 두 개가 같은 말을 하면 먼저 읽힌 쪽이 이기고, 다른 쪽이 있다는 걸 아무도 말해주지
않는다. 그건 모순 못지않은 실제 피해다. 그래서 남길 답을 둘로 늘렸다.

| 판정 | 남는가 | 왜 |
|---|---|---|
| CONTRADICTION | 남는다 (충돌) | 둘 다 따를 수 없다 |
| SAME | **남는다 (중복)** | 먼저 읽힌 쪽이 이기고 나머지는 안 보인다 |
| COMPLEMENT | 닫는다 | 둘 다 성립한다. 할 일이 없다 |
| UNRELATED | 닫는다 | 만나지 않는다 |

이미 답이 있는 쌍을 다시 묻기 위해 `--redo`를 뒀다. 판정 분포도 실행 끝에 출력한다.
기각률을 눈으로 봐야 지명 규칙을 좁힐지 넓힐지 결정할 수 있다.

## 고친 것 하나 (덤)

`claude`를 `execFile`로 부르면 stdin이 열린 채로 남아 CLI가 3초를 기다린다. 63쌍이면 3분을
버린다. `spawn` + `stdio[0] = 'ignore'`로 닫았다. **`services/draft.ts`도 같은 방식이라
같은 3초를 낸다** — 거기도 옮길지는 별도 판단.

## 두 번째 15쌍이 밝힌 것 — 모순은 손이 둘일 때 생긴다

```
contradiction 1 · same 2 · complement 4 · unrelated 8
```

발견 3건이 전부 **같은 모양**이었다.

```
1390 person claude-code  projects/firma/Firma 프로젝트 현황
2082 agent  index        projects/agent-team/memory/project_firma.md        ← 모순

1579 person claude-code  investing/할달 렌즈 프로젝트 시작
2084 agent  index        projects/agent-team/memory/project_halal_lens.md   ← 중복

1762 person claude-code  projects/opula/opula 블로그 보이스
2076 agent  index        .../memory/feedback_opula_blog_voice.md            ← 중복
```

사람이 쓴 노트 ↔ 에이전트가 쓴 자기 사본. 사람끼리 쓴 12쌍에서는 하나도 안 나왔다.
**모순은 한 머릿속이 변해서가 아니라 같은 것을 두 손이 따로 적고 서로 안 읽어서 생긴다.**

그래서 저자가 다른 쌍을 먼저 묻고, 그 쌍에만 거리 한도를 따로 둠(0.35 → 0.40). 두 사람이 같은
것을 적으면 표현이 달라 거리가 멀어진다.

### 임계값 스윈 (실측)

| 교차-저자 상한 | 후보 쌍 |
|---|---|
| 0.35 | 63 |
| 0.38 | 67 |
| **0.40** | **84** |
| 0.42 | 152 |
| 0.45 | 537 |

0.42부터 터진다. 0.40이 생긴 만큼만 열고 백로그를 만들지 않는 지점이다.

### 같이 잡은 버그

`k`는 레이어 필터보다 **먼저** 적용된다(`detectStaleState`가 같은 이유로 250을 쓴다). 초판은
25였고, 그러면 가장 가까운 25개가 대부분 `past`라 판단이 거의 안 남는다. 250으로 고쳤다.
