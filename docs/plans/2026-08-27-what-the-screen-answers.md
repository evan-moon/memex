# 화면이 답하는 질문 — 검색과 다른 형태

> `2026-08-21-ui-roles.md`가 UI를 "Claude가 대신 못 해주는 일"로 정의했고, 그 정의가
> 홈을 `9 to do today`로 만들었다. `2026-08-26-discovery-supply.md`가 "발견"을 기각하며
> 후보를 하나만 남겼다 — **읽기**. 이 문서는 그걸 재고 UI 방향을 닫는다.

## 결론

**화면의 가치는 정보 접근이 아니라 질문의 형태다.**

검색은 *"무엇이 관련 있나"* 에 답하고, 화면은 *"무엇이 지금 참인가"* 에 답한다. 후자는
볼트 전체를 한 축으로 정렬해야 나오는 답이라 대화로는 비싸다.

## 처음에 잘못 쟀다

첫 임계값은 이랬다 — *"Topic 화면이 보여주는 것 중 MCP 응답에 아예 없는 필드가 2개 이상이면
성립."* 재보니:

| Topic 화면 | MCP |
|---|---|
| 레이어 배지 | ✅ `#id [state] 제목` |
| `Superseded by #N` | ✅ `⚠️ superseded — corrected by #N` |
| `N newer notes have piled up` | ✅ `get_signals(type: stale_state)` |
| 숨은 줄기 | ✅ `get_signals(type: hidden_arc)` |
| companion 태그 + 겹침 | ❌ |
| 태그 병합 후보 | ❌ |

형식상 2개라 통과지만 둘 다 "태그 위상" 한 종류이고 읽기가 아니라 위생이다. **거의 전부
MCP로 도달 가능했다.**

그런데 필드를 세는 것 자체가 틀린 축이었다. 오늘 두 번째로 같은 실수다 — 아침엔 **선형
탐지기로 조합 문제**를 쟀고(월 3~4건은 코퍼스 총량이 아니라 지명기 수확량이었다), 여기선
**필드 존재로 형태 문제**를 쟀다. 임계값을 먼저 박는 규율은 지켰지만 **임계값이 겨냥한
대상이 틀리면 규율이 소용없다.**

## 그래서 직접 답해봤다

질문: **"memex 주제에서 내가 지금 믿는 게 뭐고, 그중 무너진 게 있나?"**

**MCP — 호출 1회, 결과 10건**

```
1. #1385 [state] Herald 에코시스템 브랜딩 & 홍보 전략     2026-05-02
2. #1455 [state] Memex 기능 카탈로그
3. #1509 [past]  추론 엔진 구현 완료
4. #1437 [past]  방향성 논의 (Gemini 2R)
...
```

- **관련도 순**이지 "지금 믿는 것" 순이 아니다. `state` 4 / `past` 6이 섞인다
- 최상위가 4개월 전 노트다
- **정정 경고가 한 건도 안 붙었다.** `supersededLine`은 구현돼 있는데, **정정된 노트 자체가
  결과에 안 들어와서** 발동을 못 했다
- "무너진 게 있나"에 답하려면 `get_signals`를 따로 불러야 한다

**Topic 화면 — 호출 0회, 한 눈**

```
Still holds 11                Old news 3
  state memex UI 감사            2 already changed · 1 to review
  state memex                    past 세션 인계 2026-08-26
  state 추론 엔진 설계 플랜             ⤷ Superseded by #2227 "[Amendment] 월 3~4건은…"
  state 코드베이스 현황            past Obsidian 정합성 재편
  state 기능 카탈로그                  ⤷ Superseded by #2216 "[Amendment] Obsidian은…"
  state 개발 노트                 state memex vs Obsidian Smart Connections
                                     ⤷ 3 newer notes have piled up since
```

**필드가 없어서가 아니었다. 관련도 랭킹이 낡음이 중요한 노트를 애초에 안 꺼낸다.**
#2222는 오늘 #2227이 정정했는데 검색 10건에 없었고, 그래서 정정 경고도 못 붙었다. 화면은
같은 것을 3순위로 보여준다.

### 공정을 위한 단서

질의가 최적이 아니었을 수 있고, Claude가 `get_signals`와 `list_notes`를 이어 부르면 비슷한
답을 조립할 수 있다. 실제 대화라면 한 번 더 좁혀갔을 것이다.

**그게 정확히 요점이다.** 화면은 **한 눈**이고, 대화는 올바른 질의 + 후속 호출 + 모델이 그
호출을 하기로 결정하는 것이 전부 맞아떨어져야 한다. `2026-08-27-three-engine-second-brain.md`가
세운 축으로 말하면 — **고정된 인간 주의력 예산 안에서** 둘의 비용이 다르다.

## `ui-roles.md`의 프레임을 고친다

원 문서:

> UI는 검색 도구가 아니다. 검색은 Claude가 대화 중에 한다(MCP-first). 사용자가 UI를 여는
> 순간은 **Claude가 대신 못 해주는 일**이 필요할 때고, 그건 세 가지뿐이다: 눈으로 확인하는
> 일, 판단하는 일, 고치는 일.

**"Claude가 대신 못 해주는 일"이라는 기준이 UI에 잔반을 배정했다.** 좋은 일은 전부 Claude
쪽이고 남은 잡일이 화면이 되니, 홈이 `9 to do today`가 된 것은 디자인 실패가 아니라 정의의
귀결이었다.

고친 기준: **UI는 Claude가 못 하는 일을 하는 곳이 아니라, 다른 형태의 질문에 답하는 곳이다.**
- 대화 — *무엇이 관련 있나.* 선형, 5건, 관련도 순
- 화면 — *무엇이 지금 참인가.* 전체, 한 축으로 정렬, 상태가 함께

원칙 하나는 살아남는다 — **UI 검색은 랭킹 품질로 Claude와 경쟁하지 않는다.** 이유가 바뀔
뿐이다. 경쟁할 필요가 없어서가 아니라 **다른 질문에 답하기 때문**이다.

## 그래서 화면은 무엇이 되나

`2026-08-26`에서 그린 3단 뼈대가 그대로 선다. 다만 각 칸의 정당화가 바뀐다.

```
┌──────────────┬─────────────────────┬────────────────────────────┐
│  주제         │  ● 지금 믿는 것 11  │  노트 본문                  │
│  지금 믿는 것 │  ○ 뒤집힌 것    3   │  ┌──────────────────────┐  │
│  지침         │    ⤷ #2227이 정정   │  │ 이 노트가 뒤집은 것   │  │
│              │    ⤷ 3개 쌓임       │  └──────────────────────┘  │
└──────────────┴─────────────────────┴────────────────────────────┘
```

가운데 칸이 이 문서가 확인한 그것이다 — **한 주제를 상태 축으로 갈라서 전부 보여주는 것.**
지금 Topic 화면이 이미 하고 있고, **앱 전체의 기본 문법으로 승격**한다.

**`오늘`(발견) 칸은 사이드바 최상단에 남기되 주력이 아니다.** 월 3~4건이라 대부분의 날은
비어 있고, 비어 있는 게 정상이다.

## Electron

명분이 셋이 됐다.

| | 근거 |
|---|---|
| 존재 | 터미널 명령이 아니라 독 아이콘. `memex ui`는 열어야 존재하는 물건이다 |
| 알림 | 발견 월 3~4건 — 화면 빈도가 아니라 알림 빈도 |
| **읽기의 일상성** | 이 문서가 확인한 것. **단, 빈도는 아직 안 쟀다** |

셋째가 제일 크고 유일하게 미측정이다. **읽기를 실제로 얼마나 자주 하는지는 쓰면서 재야
한다** — 그리고 그걸 재는 장치가 오늘 만든 `retrieval_log.initiator`다(`user_explicit`과
`agent_assisted`의 비율).

Electron 착수는 여전히 `three-engine` §11의 규모 리팩터 뒤다. 아키텍처 없이 껍데기부터
만들면 되돌리기 어렵다.

## 오늘 세션이 기각한 것

| 후보 | 결과 |
|---|---|
| 검색·대화 | Claude Desktop이 한다. 열등한 복제품 |
| 발견 | 월 3~4건. 알림은 되지만 화면은 안 됨 |
| 정비·잡일 | 원래 문제 그 자체 |
| **읽기** | **확정.** 다른 형태의 질문에 답한다 |

넷 중 하나가 남았고, 남은 이유가 처음 예상과 달랐다. 아침에 기각한 발견은 **드물어서**
화면이 안 됐고, 읽기는 **매번 필요해서** 화면이 된다.
