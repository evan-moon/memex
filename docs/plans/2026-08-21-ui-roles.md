# memex UI — 화면별 역할과 사용자 경험

> 기능 목록이 아니라 **각 화면이 무엇을 위해 존재하는가**를 정하는 문서.
> 구현 순서(M0~M5)는 이 역할 정의에서 파생된 결과다.

## 전제 — UI는 검색 도구가 아니다

검색은 Claude가 대화 중에 한다(MCP-first). 사용자가 UI를 여는 순간은 **Claude가 대신 못 해주는 일**이 필요할 때고, 그건 세 가지뿐이다: 눈으로 확인하는 일, 판단하는 일, 고치는 일.

> **memex UI = Claude의 기억을 사람이 감사(audit)하고 정비하는 곳.**
> 찾는 곳이 아니라, 확인하고 바로잡는 곳.

근거는 [[Memex Second Brain 방향성 논의 (Gemini 2R, 2026-05-24)]](#1437)에서 정한 moat 3축이다. 이 중 둘은 대화로는 채울 수 없다.

- **Interoperability** — Obsidian ↔ Claude ↔ 파일 왕복. UI가 그 교차로다.
- **Verifiability** — "AI가 왜 그렇게 생각했지?"에 원본 `.md`를 즉시 보여주는 것. 지금 memex에서 이건 구현이 아니라 **주장**이다. `save_note`가 끝나면 사용자 손에 남는 건 id 하나뿐이고, 그걸 눈으로 검증할 경로가 없다.
- Local-only privacy — 이건 아키텍처가 이미 보장.

이 프레임의 직접적 귀결: **UI 검색은 랭킹 품질로 Claude와 경쟁하지 않는다.** UI 검색의 성공 기준은 정확도가 아니라 **도달 속도**다.

## 사용자가 UI를 여는 4가지 순간

| 모드 | 언제 | 체류 | 현재 지원 |
|---|---|---|---|
| **확인** | Claude가 방금 저장한 직후 / 근거로 든 노트를 실물로 보고 싶을 때 | 30초 | ✗ 방금 들어온 게 뭔지 볼 데가 없음 |
| **점검** | 주 1회, 습관적으로 | 5분 | △ 홈이 누적 통계라 어제와 오늘이 같음 |
| **정비** | 틀린 걸 발견했을 때 | 10~30분 | △ stale state 본문 교체 하나만 가능 |
| **재발견** | 목적 없이 | 부정기 | ✗ cross-pollination이 moat인데 hidden_arc 2건뿐 |

## 원칙

1. **찾는 곳이 아니라 확인하는 곳** — 검색 품질로 Claude와 경쟁하지 않는다.
2. **모든 화면은 신선도를 말한다** — 노트든 주제든 검색 결과든 "이게 지금도 맞나"가 함께 온다.
3. **발견한 자리에서 고친다** — 관리 전용 화면도, 신호 큐도 만들지 않는다. (기존 CLAUDE.md 정책)
4. **누적이 아니라 변화** — 홈은 델타. 할 게 없으면 없다고 말한다.
5. **원본으로 나가는 문을 항상 연다** — Obsidian·파일 경로. interop이 moat다.

## 화면별 계약

각 화면이 답해야 할 질문 하나. 답하지 못하면 그 화면은 존재 이유가 없다.

### 홈 — "내가 안 본 사이에 무슨 일이 있었나"

지금은 누적 통계판이라 매일 같은 화면이다. 노트 1357개라는 숫자는 신뢰 지표지 방문 이유가 아니다.

- 홈은 **델타**다: 새로 들어온 것, 새로 썩은 것, 손볼 것 0~3개.
- 할 게 없으면 **0을 당당하게 말한다.** "다 정리됐어"가 유효한 홈 화면이다.
- 통계와 활동 차트는 신뢰 지표로 하단에 남긴다.
- 재발견 한 칸("오늘의 연결")을 둔다 — `note_links.source='flashback'` 데이터가 이미 쌓여 있다.

### 주제 — "이 주제에 대해 내가 지금 뭘 믿나"

가장 잘 만들어진 화면. 폴더가 아니라 주제로 자르는 것이 memex UI의 정체성이다.

- 격차는 **시간 서사**다. 스파크라인은 '양'만 말하고 '언제 생각이 바뀌었나'는 말하지 못한다. amends 체인이 있으니 입장이 뒤집힌 지점을 시간축에 찍을 수 있다.
- 정렬이 '낡은 것 순' 하나뿐인데 그건 정비 모드 기준이다. 확인 모드에는 '최근 움직인 순'이 필요하다.

### 노트 — "이 기억은 아직 유효한가, 어디서 왔나"

문서 뷰어가 아니라 **판정대**. StalePanel이 정확히 그 방향이고 이 앱에서 가장 잘 만든 조각이다.

- 판정 뒤의 행동이 반쪽이다. state 본문 교체만 되고, past에 정정 노트를 못 쓰고, 태그·레이어를 못 고치고, 깨진 링크 170건은 보이지도 않는다.
- Verifiability 축에서 빠진 것: 이 노트가 어느 대화에서 왔는지(`source`), 원본으로 나가는 문, 이 노트를 근거로 만들어진 추론.

### 검색 — "아는 걸 다시 찾아가는 통로"

답변 엔진이 아니라 **점프대**.

- 필요한 것은 정교한 랭킹이 아니라 ⌘K 팔레트(제목 즉시 매칭 우선, 의미 검색은 보조), 최근 방문, 필터.
- 결과에는 **상태 배지**가 붙는다(정정됨 / 낡음 / 중복 후보). 그 순간 검색도 감사 도구가 된다.

### 사이드바 — 지금 정체성이 없다

state 242 + past 1104 + rule 11을 전부 나열해 사실상 파일 탐색기다. 주제 축과 레이어 축이 한 화면에서 경쟁하고, 1104개를 300개씩 페이징하는 건 그 혼란의 증상이다.

- **결정: 주제 중심으로 압축한다.** past 나열은 검색·주제에 위임하고, 사이드바는 `주제` + `지금 믿는 것` + `지침`만 남긴다.

## 확정된 결정

| 결정 | 내용 |
|---|---|
| 언어 | i18n 레이어. 기본 `en`, 한국어 로케일 제공 |
| 쓰기 범위 | 편집 + 정정까지. state/rule 인라인 편집, 태그 수정, past에 대한 정정 노트. **삭제·병합은 CLI에 남긴다** |
| 사이드바 | 주제 중심으로 압축 |
| 첫 화면 | 달라진 것(델타) |

## 마일스톤

### M0 — i18n 뼈대 (선행 조건)

새 카피를 한국어로 박았다가 다시 뜯는 걸 막기 위해 M1보다 먼저 간다.

- `apps/ui/src/i18n.ts` — `en`/`ko` 사전(`as const`), `useT()`, 폴백은 localStorage → `navigator.language` → `en`. 조회는 dispatch table.
- 기존 카피 약 120개 전량 이관(8개 파일). 절반만 이관하면 최악이므로 한 번에 끝낸다.
- 헤더에 언어 토글(테마 토글 옆).
- **서버가 사람이 읽는 문장을 만들지 않게 한다.** 현재 `services/ui/topics.ts`가 `#123 "제목" 에서 이야기가 바뀌었어` 같은 완성된 한국어 문장을 API로 내려보내고 있어 번역이 불가능하다. 구조화된 형태로 바꾼다:
  - `reason: string` → `reason: { kind: 'amended', by: NoteRef } | { kind: 'piled-up', count: number }`
  - `server.ts`의 오류 메시지(`state 노트만 갱신 초안을 만들 수 있어.` 등)도 코드로 내려보내고 문구는 클라이언트가 고른다.

### M1 — 홈을 델타로 (모드: 확인 · 점검)

- `apps/cli/src/services/digest.ts` 신설. 폴더 그룹핑·신호 집계 로직이 지금 `commands/digest.ts` 안에 인라인이라 재사용이 안 된다. 순수 함수로 빼내고 CLI는 출력만, UI는 JSON만 담당.
- `GET /api/digest?days=7`
- `ThisWeek.tsx` — 홈 최상단. 새로 들어온 것(폴더별) / 손볼 것 0~3개(클릭 → 노트의 StalePanel로 직행) / 오늘의 연결.
- 0 상태 카피를 1급으로 취급한다.
- 신선도 배지 컴포넌트를 `bits.tsx`에 추가하고 모든 노트 목록(검색·주제·백링크·related)에 적용 — 원칙 2.
- 기존 통계·활동 차트는 하단으로 이동.

### M2 — 도달 (모드: 확인)

- `Palette.tsx` — ⌘K. 제목 substring 즉시 매칭(로컬 인덱스)을 먼저 보여주고, 의미 검색은 디바운스 후 아래에 덧붙인다. 최근 방문은 localStorage.
- `GET /api/titles` — id·title·layer만. 사이드바가 놓은 일을 여기가 받는다.
- 검색 필터: layer / tag / folder / 기간. 상태는 전부 URL 쿼리스트링(새로고침·공유 유지). 더 보기 페이징.
  - `SearchOptions`에 `category/tag/dateFrom/dateTo`는 있으나 **`layer`가 없다** → `packages/core`에 한 줄 추가.
  - `searchPage`가 돌려주는 `collapsed`(시리즈 접힘)를 지금 버리고 있다 → "같은 시리즈 N건 접힘"으로 노출.
- 사이드바 재구성(주제 + 지금 믿는 것 + 지침). `/api/sidebar`가 1357개를 통째로 내려보내던 것도 여기서 해소된다.

### M3 — 노트 판정대 완성 (모드: 정비)

- 인라인 편집: 제목·본문·태그·레이어. state/rule 대상.
- past → "이건 이제 틀렸어" → 정정 노트 작성. **`editNote`가 이미 `PAST_IMMUTABLE` 거절에 `suggestion: { action:'save_note', title, link, layer, amends }`를 담아 돌려준다** — UI는 그 suggestion을 폼으로 렌더하기만 하면 된다.
- 깨진 링크 170건: 본문 렌더에서 미해결 `[[...]]`를 표시하고 후보 제안(유사 제목) 또는 새 노트 만들기. 큐 화면 없이 노트 안에서 — 원칙 3.
- 태그 이름 바꾸기·합치기. 홈의 tidy 제안이 CLI 안내 대신 버튼이 된다.
- 낙관적 반영 + 실패 시 복구.

### M4 — 세계관 (모드: 확인)

- `/believe` — state 242개를 주제별로 접은 화면. 사실상 "내 세계관 요약".
- 주제 화면에 시간 서사: amends 체인을 시간축에 찍어 입장이 바뀐 지점을 보여준다.
- 주제 목록 정렬 전환(최근 순 / 낡은 순).

### M5 — 재발견과 라이브 (모드: 재발견)

- flashback · hidden_arc · inference를 맥락 속 카드로. inference는 근거 노트 + stale 표시 + 폐기까지.
- SSE로 노트 변경 브로드캐스트 → 대화 옆에 띄워두면 Claude가 저장하는 순간 홈에 나타난다. Verifiability를 주장이 아니라 감각으로 만드는 장치.

## 하지 않는 것

- **신호 큐 화면** — 신호는 맥락 속 주석으로만 등장한다(CLAUDE.md 정책).
- **삭제·병합** — 되돌리기 어려운 쓰기는 CLI에 남긴다.
- **인증·원격 접속** — loopback 전용을 유지한다.
- **그래프 시각화** — 방향성 논의에서 이미 우선순위에서 내려간 항목.
- **대화 자동 ingest** — DB 오염. #1437에서 명시적으로 금지.

## 남은 이슈

- `apps/cli/src/services/ui/page.ts`(828KB 생성물)가 커밋돼 있어 UI를 건드릴 때마다 diff가 거대해진다. npx 설치 때문에 의도된 것으로 보여 그대로 두지만, 리뷰 부담은 실재한다.
- `apps/ui`·`services/ui` 코드에 설명 주석이 다수 있는데 전역 스타일 가이드는 주석 금지다. 새 코드는 무주석으로 가고, 기존 정리는 별도 판단.
