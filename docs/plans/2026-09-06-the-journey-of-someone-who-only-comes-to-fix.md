# 고칠 때만 오는 사람의 저니

> 운영 계약 #2280 §3 승인 요청서. 현재 상태를 먼저 그리고, 미래 상태는 그 차이로만 적는다.
> 한 사람, 한 시나리오. 볼트 주인이 "AI가 뭔가 이상하게 안다"는 낌새로 앱을 여는 경우.
> 근거는 로그와 이 세션에서 실측한 숫자다. 사람을 인터뷰한 적은 없다. 그래서 감정 행은 추정이고, 그렇게 표시한다.

## 0. 이 사람

**볼트 주인. 비개발자.** 하루를 Claude Code나 Codex 대화 안에서 보낸다.
앱은 평소 열지 않는다 — 전체 읽기의 0.36%, 열린 날은 하루(`2026-09-04-who-actually-reads-memex.md`).

이 사람이 앱을 여는 이유는 셋뿐이다(#2280 §2).

| 촉발 | 빈도 | 이 문서 |
|---|---|---|
| AI가 뭔가 이상하게 안다는 **낌새** | 가끔 | **이 문서의 시나리오** |
| 중요한 일을 맡기기 전 **점검** | 드물게 | 같은 저니. 진입만 다르다 |
| **처음 설치** | 한 번 | 별도 (온보딩은 이미 있다) |

이 사람은 브라우징하러 오지 않는다. 그건 #2280이 폐기한 가설이다.

## 1. 현재 상태

### 단계

```
낌새 ──▶ 열기 ──▶ 찾기 ──▶ 판정 ──▶ 고치기 ──▶ 닫기 ──▶ 다음 대화
```

### 단계별

| | 낌새 | 열기 | 찾기 | 판정 | 고치기 | 닫기 | 다음 대화 |
|---|---|---|---|---|---|---|---|
| **목표** | 이게 AI 탓인지 안다 | 어디부터 볼지 안다 | AI가 그걸 뭐라고 아는지 본다 | 맞는지 틀린지 정한다 | 틀린 걸 바로잡는다 | 끝났다는 감각 | 고친 게 반영됐는지 안다 |
| **행동** | 대화에서 이상한 답을 본다 | 앱을 연다 | 검색하거나 트리를 뒤진다 | 카드를 넘긴다 | `바뀌었어요`를 누른다 | 세션이 닫힌다 | 같은 걸 다시 묻는다 |
| **접점** | Claude Code | 홈 | 검색 · 사이드바 트리 | 카드 덱 | 카드 → (없음) | 완료 화면 | Claude Code |
| **생각** | "이거 내가 말한 적 없는데?" | "어디를 봐야 하지" | "이 노트가 그 얘기인가?" | "이게 아직 맞나?" | "지금 뭐가 맞더라…" | "이제 됐나?" | "고친 게 먹었나?" |
| **감정** (추정) | 불신 | 막막함 | 헤맴 | 집중 | **막힘** | 안도 | **의심** |

### 아픈 곳

번호는 뒤의 미래 상태에서 그대로 쓴다.

**P1 · 사이드바가 다섯 가지 언어로 말한다.** 볼트 / 주제 / 지금 믿는 것 / 지침 / 줄기.
저장 구조(폴더), 태그, 레이어 이름의 번역(`state`→"지금 믿는 것", `rule`→"지침"), 그리고 비유(줄기).
비개발자가 "지금 믿는 것"과 "지침"의 차이를 알 방법이 없다. 같은 것을 부르는 이름이 화면마다 다르다.

| 같은 것 | 사이드바 | 화면 제목 | 덱 카드 |
|---|---|---|---|
| `rule` 노트 | 지침 | 지침 | 승인을 기다리는 규칙 |
| `state` 노트 | 지금 믿는 것 | (없음) | — |
| register | (없음) | 지금 참인 것 | — |

**P2 · 화자가 셋이다.** 규칙·값·연결 화면은 AI가 "제가"로 말하고, 덱은 앱이 AI를 3인칭으로 부르고,
온보딩은 memex가 말한다. "저"가 누군지 화면마다 다르다. 제품 정의상 memex는 AI가 쓰는 도구이지
AI 자신이 아니다. 앱이 AI 목소리로 말하면 감독 대상과 감독 도구가 섞인다.

**P3 · 목적지가 열여섯 개다.** `/`, `/today`, `/topic`, `/threads`, `/thread`, `/note`, `/search`, `/tags`,
`/rules`, `/register`, `/register/:subject`, `/repair/evidence`, `/inference`, `/settings`, `/chat`, `/connect`.
이 사람이 실제로 필요한 건 셋이다. 나머지는 개발자 진단 화면이거나 다른 화면 안에서 닿아야 할 것이다.

**P4 · 고치기가 막다른 길이다.** `바뀌었어요`가 "틀렸다"고 표시만 하고 새 값을 받지 못한다(1차 범위).
그리고 사람도 값을 모른다 — 덱 주장의 나이 중앙값 52일(`2026-09-06-suggesting-the-correction.md`).

**P5 · 판정이 AI에 닿지 않는다.** `note_claims`를 읽는 곳은 `deck.ts` 하나다.
확인해도 다음 대화에서 AI가 하는 말은 같다. 규칙 승인만 예외다.
그래서 마지막 단계 "다음 대화"의 감정이 의심으로 끝난다. **이게 저니 전체에서 가장 아픈 곳이다.**
루프가 닫히지 않으면 앞의 여섯 단계가 헛수고로 느껴진다.

**P6 · 개발자 어휘가 화면에 샌다.** `past가 되면`, `state 노트만`, `diff`, `index`, `git`, `PATH`, `프론트매터`, `CLI`.

### 결정적 순간

| | 언제 | 지금 | 
|---|---|---|
| **M1 첫 카드** | 열자마자 카드 하나가 뜬다 | 된다. 주장이 20px로 서 있고 "왜 나한테 왔는지"(N번 썼어요)가 붙어 있다 |
| **M2 고치기** | `바뀌었어요`를 누른 뒤 | **안 된다.** 표시만 되고 값을 받을 자리가 없다 |
| **M3 다음 대화** | 고친 다음 날 같은 걸 물었을 때 | **안 된다.** 판정이 회수에 안 닿는다 |
| **M4 빈 상태** | 세션이 닫힐 때 | 된다. "오늘 몫은 여기까지예요" |

Peak-End 규칙대로면 사람은 M1과 M4를 기억한다. 둘 다 되고 있다.
하지만 M3가 안 되면 두 번째 방문이 없다. 첫 방문의 좋은 기억이 두 번째 방문을 만들고,
두 번째 방문에서 "고친 게 안 먹었네"를 확인하면 끝이다.

## 2. 미래 상태

현재 상태에서 바뀌는 것만 적는다. 안 적힌 건 그대로다.

### 목적지를 셋으로 줄인다 (P1 · P3)

이 사람의 세 가지 일에 화면 하나씩.

| 일 | 화면 | 답하는 질문 | 기본 행동 |
|---|---|---|---|
| **확인하기** | 홈 `/` | AI가 말한 것 중 내가 봐야 할 게 뭔가 | 카드 넘기기 |
| **찾기** | 검색 `/search` | AI가 X를 뭐라고 아는가 | 검색 |
| **고치기** | 대화 `/chat` | 틀린 걸 어떻게 바로잡나 | 말하기 |

여기에 **노트**(트리, 원문을 읽을 때)와 **설정**(연결 포함)이 붙는다. 사이드바는 다섯 줄이 된다.

```
확인하기
찾기
고치기
──────
노트
설정
```

내려가는 것:

| 지금 사이드바에 있는 것 | 어디로 |
|---|---|
| 주제 | 검색 필터. 태그로 거르기 |
| 지금 믿는 것 (`state`) | 검색 필터. "현재 믿음만" |
| 지침 (`rule`) | 덱 카드로 온다 (이미 그렇다). 목록은 설정 → 규칙 |
| 줄기 | 노트 화면 안. 정정된 노트에서 "정정 흐름 보기" |
| `/today` 정리 작업 | 설정 → 볼트 정리. 기억 감독이 아니라 파일 정리다 |
| `/register` | 노트 화면 안. 그 주제의 값 |
| `/repair/evidence` | 설정 → 볼트 정리 |
| `/tags` | 설정 → 볼트 정리 |

**라우트는 지우지 않는다.** 사이드바에서 빼고 다른 화면 안에서 닿게 한다. #2280이 라우팅 변경을 승인 없이 금지하고, 이 문서가 그 승인 요청이다.

### 화자를 하나로 한다 (P2)

**앱은 앱으로 말한다.** AI는 "AI"다. "저/제가"는 대화 화면(`/chat`) 안의 AI 발화에만 남는다.

| 지금 | 바뀜 |
|---|---|
| 제가 스스로 지킬 규칙으로 적어 둔 것들이에요 | AI가 자기 규칙으로 제안한 것들이에요 |
| memex는 제가 기억을 두는 곳이에요 | AI가 기억을 두는 곳이에요 |
| 주제마다 제가 들고 있는 값이에요 | AI가 주제마다 들고 있는 값이에요 |

이유는 제품 정의다. memex는 AI의 해마이지 AI가 아니다. 감독 도구가 감독 대상의 목소리로 말하면
사람은 누구를 믿고 누구를 의심해야 하는지 알 수 없다.

### 이름을 하나로 한다 (P1)

| 것 | 이름 | 버리는 이름 |
|---|---|---|
| `rule` | **규칙** | 지침 |
| `state` | **현재 믿음** | 지금 믿는 것 |
| register | **기록된 값** | 지금 참인 것 |
| `past` | **기록** | (원어) |
| threads | **정정 흐름** | 줄기 |
| `/today` | **볼트 정리** | 볼 것 · 오늘 할 일 |
| inference | **가설** | 추론 (혼용) |
| agent | **AI** | 에이전트 (혼용) |

#2280과 #2288이 이미 "규칙"과 "현재 믿음"을 쓴다. UI만 다른 이름을 쓰고 있었다.

### 고치기를 닫는다 (P4 · P5)

이 문서가 정하지 않는다. 각각 담당 문서가 있다.

- **M2 고치기** → `2026-09-06-suggesting-the-correction.md`. 볼트에서 후보를 찾아주고, 모르면 `모르겠어요`로 닫는다
- **M3 다음 대화** → #2288 §8·§9. `confirmed` 우선 주입, `unconfirmed` 가중치 하락, 시점 부착

이 둘이 없으면 사이드바를 아무리 줄여도 저니는 의심으로 끝난다. **순서는 M3가 먼저다.**
고치기가 화려해도 반영이 안 되면 의미가 없고, 반영만 되면 지금의 "틀렸다 표시"로도 루프가 닫힌다.

### 화면이 개발자 말을 하지 않는다 (P6)

원어 레이어 이름, git, diff, index, PATH, 프론트매터, CLI를 화면에서 뺀다.
비개발자에게 "git 기록에는 남아 있어요"는 안심이 아니라 소음이다.
파일이 지워지는 사실만 말하고, 복구는 설정 → 볼트 정리에서 다룬다.

## 3. 바뀌는 것의 크기

| 항목 | 종류 | 크기 | 이 문서에서 |
|---|---|---|---|
| 화자 통일 · 이름 통일 · 개발자 어휘 제거 | 문구 | `i18n.ts` 한 파일 | **바로 한다** |
| 사이드바 5줄 | 셸 | `Sidebar.tsx` | 승인 후 |
| 내려간 화면을 다른 화면 안에서 닿게 | 셸 | 노트 화면 · 설정 화면 | 승인 후 |
| M2 고치기 | 기능 | 별도 지시서 | 별도 |
| M3 반영 | 기능 | #2288 2차 | 별도 |

문구는 셸을 안 건드리므로 먼저 간다. 사이드바는 이 문서의 승인을 기다린다.

## 4. 이 저니가 틀렸다는 신호

| 관측 | 뜻 |
|---|---|
| 사이드바를 줄인 뒤 검색 사용이 늘지 않음 | 주제·현재 믿음을 검색 필터로 내린 게 틀렸다. 사람은 목록으로 훑고 싶어 했다 |
| 두 번째 방문이 M3 전에 일어남 | "고친 게 먹었나"가 방문 이유가 아니다. 낌새만으로 온다 |
| `/today` 정리 작업을 설정에서 아무도 안 찾음 | 정리는 앱이 할 일이지 사람이 할 일이 아니었다. 자동화한다 |

## 5. 승인이 필요한 것

1. 사이드바를 **확인하기 · 찾기 · 고치기 · 노트 · 설정** 다섯 줄로 줄이는 것
2. 주제 · 현재 믿음 · 규칙 목록 · 정정 흐름 · 볼트 정리를 사이드바에서 빼고 다른 화면 안에 두는 것
3. 화자를 앱 하나로 통일하고 "저/제가"를 대화 화면에만 남기는 것
4. 이름 여덟 개를 위 표대로 통일하는 것
5. 개발자 어휘를 화면에서 빼는 것
6. M3(판정 반영)를 M2(고치기 제안)보다 먼저 하는 것

3·4·5는 문구라서 이 문서와 같이 바로 들어간다. 1·2는 승인을 기다린다.
