# 일마다 다른 모델 — 승인 요청서

> 운영 계약 memex #2280 §3에 따른 승인 요청서. 코드는 아직 안 건드렸다.
> Aside의 Settings › Models(`Default / Fast / Standard / Deep / Visual`)를 보고 시작했지만,
> 그 다섯을 베끼는 게 아니라 **memex가 실제로 부르는 다섯 자리**를 재고 나눈다.

## 0. 실측 — 지금 누가 무엇으로 부르나

| 자리 | 파일 | 지금 모델 | provider | 누가 누르나 |
|---|---|---|---|---|
| 대화 턴 | `chat/turn.ts:492` | 사람이 고른 것 | 둘 다 | 사람, 매 턴 |
| state 초안 | `draft.ts:153` | 고른 것 / `sonnet` | 둘 다 | 사람이 누름 |
| 추론 다시 쓰기 | `inference-draft.ts:57` | 고른 것 / `sonnet` | 둘 다 | 사람이 누름 |
| claim 추출 | `claim-extract.ts:54` | **`sonnet` 고정** | **claude 고정** | 앱이 뒤에서 |
| 충돌 판정 | `conflicts.ts:71` | **`sonnet` 고정** | **claude 고정** | `memex signals conflicts` |

**아래 둘은 사람이 손댈 수 없다.** `askClaude`를 직접 부르므로 codex를 쓸 수 없고,
모델도 못 바꾼다. 어제 만든 피커가 닿지 않는 자리다.

## 1. 축 — 무엇이 이 다섯을 가르나

기능 이름으로 나누면 기능이 늘 때마다 깨진다. Aside가 성격으로 나눈 이유이고, memex에서
성격을 가르는 것은 **누가 기다리는가**다.

| | 사람이 기다리나 | 얼마나 | 몇 번 도나 | 틀리면 |
|---|---|---|---|---|
| 대화 턴 | **예, 보면서** | 초 | 턴마다 | 그 자리에서 다시 말한다 |
| 초안 (state·추론) | 예, 기다린다고 화면이 말함 | 1~2분 | 누를 때 | **사람이 승인 전에 잡는다** |
| claim 추출·충돌 | **아니오** | 상관없음 | 노트·쌍 수만큼 | 신호가 조용히 틀린다 |

세 줄이 서로 다른 모델을 원한다. 대화는 **빠르고 괜찮은 것**, 초안은 **느려도 제일 좋은 것**,
훑기는 **싼 것**. 지금은 셋 다 `sonnet`이다.

## 2. 제안 — 일 셋

| 이름 | 무슨 일인지 (화면에 적을 말) | 지금 자리 |
|---|---|---|
| **대화** | 앱에서 주고받는 말. 사람이 보고 있어요 | `chat/turn.ts` |
| **초안** | 사람이 승인할 글을 써요 | `draft.ts` · `inference-draft.ts` |
| **훑기** | 노트를 기계적으로 훑어요. 사람은 안 기다려요 | `claim-extract.ts` · `conflicts.ts` |

Aside의 `Visual`은 만들지 않는다 — memex는 이미지를 안 읽는다. `Image generation`도 없다.
넷째를 미리 파두지 않는 이유는, 이름이 일의 성격이어야 하는데 지금 memex에 넷째 성격이 없기
때문이다.

## 3. 어디에 저장하나 — 여기가 진짜 결정이다

지금 기본값은 `localStorage['memex-model']`에 있다. **훑기는 거기 못 닿는다.**
`claim-extract`는 앱 호스트가 뒤에서 부르고 `conflicts`는 CLI 명령이다. 브라우저 저장소는
둘 다 못 읽는다.

그래서 배정은 `~/.memex/config.json`으로 간다. `loadConfig`가 이미 부분 객체를 병합하므로
키 하나 늘리는 것은 예전 파일과 호환된다.

```json
{
  "vault_path": "…",
  "models": {
    "chat":   { "provider": "claude-code", "model": "sonnet" },
    "draft":  { "provider": "claude-code", "model": "opus" },
    "sweep":  { "provider": "claude-code", "model": "haiku" }
  }
}
```

`models`가 없으면 셋 다 지금 값(`claude-code`/`sonnet`)이다. **기본 동작은 안 바뀐다.**

localStorage의 기존 값은 `chat`의 초기값으로 한 번 옮기고 키를 지운다.

## 4. 화면 — Settings 안, 지금 자리 그대로

지금 「생각하는 앱」 섹션에 피커 하나가 있다. 그 자리에 세 줄이 된다.

```
┌──────────────────────────────────────────────────────────┐
│ 모델                                                      │
│                                                          │
│  대화                              [ Claude Sonnet  ⌄ ]   │
│  앱에서 주고받는 말. 사람이 보고 있어요                      │
│                                                          │
│  초안                              [ Claude Opus    ⌄ ]   │
│  사람이 승인할 글을 써요                                    │
│                                                          │
│  훑기                              [ Claude Haiku   ⌄ ]   │
│  노트를 기계적으로 훑어요. 사람은 안 기다려요                 │
└──────────────────────────────────────────────────────────┘
```

피커는 어제 만든 것을 그대로 쓴다. 새 화면도 새 컨트롤도 없다.

## 5. 인라인 피커는 무엇이 되나

지금 대화 하단과 낡은-노트 패널에 각각 피커가 있고, 둘 다 `useState(defaultChoice)`라
**이번 한 번만** 바꾸고 저장하지 않는다. 그 성질을 그대로 둔다.

| | 무엇을 정하나 | 남나 |
|---|---|---|
| Settings의 세 줄 | 그 일의 기본값 | 남는다 (`config.json`) |
| 대화 하단 피커 | 이 대화 | 안 남는다 |
| 낡은-노트 패널 피커 | 이 초안 한 번 | 안 남는다 |

Aside도 같은 모양이다(`defaultModel` + 대화별 전환). 바꾸는 것은 기본값이 **하나에서 셋으로**
늘어나는 것뿐이다.

## 6. 구현 범위

| 하는 것 | 안 하는 것 |
|---|---|
| `config.json`에 `models` 셋 | 새 일 이름 추가 (Visual 등) |
| `claim-extract`·`conflicts`가 `choice`를 받게 열기 | 비용·토큰 표시 |
| 서버가 일별 배정을 읽어 각 자리에 전달 | 자동 배정 (싼 모델로 알아서 내리기) |
| Settings 세 줄 | 새 화면 · 새 컨트롤 |
| localStorage → config 이관 1회 | 대화별 기본값 기억 |

`claim-extract.ts`와 `conflicts.ts`가 `askClaude`를 직접 부르는 것을 끊는 게 실제 작업의
대부분이다. 나머지는 이미 `choice`를 받는다.

## 7. 검증할 실제 상태

1. `config.json`에 `models`가 없는 볼트에서 셋 다 지금과 같이 동작하는가
2. 훑기를 codex로 배정하면 `memex signals conflicts`가 실제로 codex를 부르는가 —
   **CLI에서 확인한다. 앱만 보면 이 자리는 안 보인다**
3. 배정한 모델의 CLI가 없을 때 무엇이 되는가. 지금 폴백은 티어 이름이고, 없는 provider는
   `not-installed`로 떨어진다. **화면이 그걸 말하는지 확인해야 한다**
4. 대화 중간에 하단 피커를 바꿔도 Settings의 값이 안 바뀌는가
5. 긴 한국어 라벨과 작은 창에서 세 줄이 안 깨지는가
6. 키보드·다크/라이트

## 8. 승인이 필요한 것

1. 일을 **셋**으로 자르는 것 (대화 · 초안 · 훑기)
2. 배정을 `config.json`에 두는 것 — localStorage로는 훑기에 닿지 않으므로
3. 인라인 피커를 "이번 한 번"으로 유지하는 것
4. 기본값을 지금과 똑같이 두는 것 (셋 다 `claude-code`/`sonnet`, 사람이 바꾸기 전까지)
