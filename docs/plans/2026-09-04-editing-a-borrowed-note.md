# 가져온 노트를 고친다 — 정보 구조 승인 요청

> 운영 계약 memex #2280 §3에 따른 승인 요청서. 코어(권한과 프론트매터 안전)는 구현·검증
> 끝났고, 이 문서는 **화면**만 다룬다. 승인 전에는 UI를 건드리지 않는다.

## 무엇이 이미 끝났나

`editNote`가 볼트 밖 파일을 사람에게 열어줬다. 검증한 것 넷:

```
에이전트는 거부되고 파일은 그대로다
사람은 통과한다
memex 필드가 남의 프론트매터에 안 박힌다 (subTitle · date 보존)
편집이 재색인을 견딘다
```

규칙 한 줄: **memex는 자기 볼트 안에서만 프론트매터를 소유한다.** 밖에서는 본문만 쓴다.

## §3-1. 이 화면이 답할 질문 하나

> 이 글은 내 것인데, 여기서 고쳐도 안전한가?

## §3-2. 기본 행동 하나

**고치기.** 직접 쓰거나, AI에게 초안을 시키고 확인한다.

## §3-3. 정보 위계 3단계

| 단계 | 무엇 |
|---|---|
| **1** | 본문과 연필 — 다른 노트와 똑같이 |
| **2** | 이 파일이 어디 것인지 한 줄 + AI에게 초안 시키기 |
| **3** | 원본 경로, 마지막 색인 시각 |

## §3-4. 제거하거나 낮출 것

| 지금 | 바꿈 |
|---|---|
| 자물쇠 아이콘 + "읽기 전용" | **삭제.** 이제 읽기 전용이 아니다 |
| 연필 없음 | **연필 표시.** 다른 노트와 같다 |
| "이 노트에 대해 쓰기" 제안 | 남기되 2단계로 |

## §3-5. 텍스트 와이어프레임

### 정상 — 가져온 노트를 열었을 때

```
┌───────────────────────────────────────────────────────────┐
│ evan-blog / 작성 2026-04-28 · MCP  Tool Calling            │
│                          내 블로그 파일이에요  [✎ 고치기]   │  ← 1단계
├───────────────────────────────────────────────────────────┤
│                                                           │
│   Tools Live On After Leaving Their Maker                 │
│                                                           │
│   첫 문단이다.                                             │
│   …                                                       │
│                                                           │
├───────────────────────────────────────────────────────────┤
│ AI는 이 파일을 스스로 고치지 않아요.                          │  ← 2단계
│ 고칠 내용을 말하면 초안을 만들어 드릴게요.                     │
│ [ 초안 만들기 ]                                            │
│                                                           │
│ ~/dev/playground/evan-blog/content/posts/…/en.md          │  ← 3단계
└───────────────────────────────────────────────────────────┘
```

### 초안이 온 뒤 — 기존 diff 장치를 그대로 쓴다

```
┌───────────────────────────────────────────────────────────┐
│ 이렇게 고칠까요?                                            │
│                                                           │
│  - 첫 문단이다.                                            │
│  + 첫 문단을 이렇게 고쳤다.                                  │
│                                                           │
│ 왜 이렇게 고쳤는지                                          │
│   …AI가 쓴 한 문단…                                        │
│                                                           │
│ [ 이대로 저장 ]   [ 다시 써줘 ]   [ 취소 ]                   │
└───────────────────────────────────────────────────────────┘
```

`StalePanel`이 이미 쓰는 `api.draft` → `DiffView` → 저장 흐름과 같다. **화면을 새로 만들지
않는다.**

### 빈 상태 — 초안을 만들 수 없을 때

```
│ 초안을 만들지 못했어요                                       │
│ Claude를 찾을 수 없어요. 직접 고치시면 돼요.                  │
│ [ 직접 고치기 ]                                            │
```

### 오류 — 파일이 사라졌을 때

```
│ 원본 파일을 찾지 못했어요                                    │
│ 옮겨졌거나 지워졌을 수 있어요. 저장하면 새로 만들어져요.        │
│ [ 원본 위치 보기 ]   [ 그래도 저장 ]                         │
```

## 구현 범위

| 하는 것 | 안 하는 것 |
|---|---|
| `writable`이 볼트 안팎을 가르지 않게 함 | 다른 화면 일체 |
| 자물쇠 → 연필 | 홈 (다음 작업) |
| "내 블로그 파일이에요" 한 줄 | 새 diff 화면 |
| 초안 프롬프트를 가져온 파일용으로 분기 | 레이어 표시 개편 |

지금 `draftStateUpdate`는 state 전용이고 프롬프트가 "낡은 state를 최신으로"다.
가져온 파일에는 **"사용자가 말한 대로 이 글을 고쳐라"**가 필요하므로 분기 하나를 만든다.
`draft-state-only` 거부는 그대로 두되 가져온 노트는 새 경로로 보낸다.

## 검증할 실제 상태

1. 가져온 노트에 연필이 보이고, 눌러서 고치고, 저장이 파일에 닿는가
2. 저장한 파일의 프론트매터가 그대로인가 (`subTitle`·`date`·`tags`)
3. `memex index` 뒤에도 고친 내용이 남는가
4. MCP로 에이전트가 같은 노트를 고치려 하면 여전히 거부되는가
5. Claude가 없을 때 빈 상태가 뜨는가
6. 긴 한국어 제목과 작은 창에서 라벨이 안 깨지는가
7. 키보드·포커스·다크/라이트

**실제 Electron 창을 캡처해서 본다.**

## 승인이 필요한 것

1. 자물쇠를 없애고 연필을 다는 것
2. "AI는 이 파일을 스스로 고치지 않아요"를 2단계에 두는 것 (1단계로 올릴지)
3. 초안을 기존 diff 장치로 받는 것
4. 가져온 파일용 초안 프롬프트를 따로 두는 것
